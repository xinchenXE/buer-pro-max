# 完成宣告与闭环仪式

> 一次「干完了」由**固定步骤**构成。步骤不做 = **没完成**，不是「差不多」。
> 这是整套框架里**对执行者约束最强**的部分，也是最容易被跳过的部分。

---

## 一、三档步数 【必选】

| 档 | 步数 | 步骤 |
|---|---|---|
| 轻量 | 3 | ① 计划内勾选 + 验证记录 ② 逐轮记录追加章节 ③ 归档（移动，不是复制） |
| 标准 | 5 | ① 计划内勾选 ② 逐轮记录 ③ **索引的「最近 N 轮」** ④ **代码地图同步** ⑤ 归档 |
| 完整 | 7 | 标准五步 + **代码/文件修改记录** + **收尾快照** |
| 重型 | 7 + 2 | 同完整，**再加两个发布期步骤**：**发布前置检查** + **发布台账登记**（均需双人签署，见 `tier-selection.md` §五） |

---

## 二、标准五步（原文照搬，逐条说明为什么） 【必选 · 标准档起】

### 1. 计划文档内：任务勾选 + 验证记录 + 偏差记录

- **任务勾选**：逐条 `[x]`，**未做的保持 `[ ]` 并写明为什么**。
- **验证记录**：每道门的结果、退出码、日志路径。
- **偏差记录**：实施中与计划不符之处，**编号追加**，不静默改道。

### 2. 逐轮记录：追加轮次章节

在「项目总结」类的活文档里追加一节，包含：
**落地 / 验证 / 偏差 / 仍开放** 四块。

- **章节号与轮次号一一对应**，是 ID 序列的一部分。
- **只追加，不改写**既有章节。历史章节是**冻结面**——它记录的是「当时真的发生了什么」，
  改写它等于篡改账本。

### 3. 索引的「最近 N 轮」状态块

更新活跃目录索引里的状态块：**日期 + 轮次 + 摘要 + 证据索引**，并指向新的章节。

> **不要无限累积状态行。** 历史上出现过一份索引里堆了 359 行逐轮状态，
> 与逐轮记录、与清册三处重复，最终只能整体冻结存档。
> **正确形态是：只保留最近 N 轮（通常 3 轮），更早的指向逐轮记录。**

### 4. 代码地图同步

更新索引里的三节：

- **可写范围**（档位/冻结符号/可改性有变化时）
- **代码结构**（新顶层目录或新分层时）
- **文件作用清单**（本轮增删改名移动的文件逐条落表；作用有实质变化的既有文件**改写其行**）

同轮把闭环计划从活跃表移除、把被吸收的待办行一并删除（**不留双份记录**），
并把三节标题的日期与基线文件数改为**当轮实测值**。

### 5. 归档：**移动**计划 + 修正全部路径引用

- 计划件从活跃目录**移动**到归档目录；
- 修正索引与清册里的**全部路径引用**；
- 计划中**派生的未完成项另立新计划**留在活跃目录。

> ⚠ 这一步是「两步」，很多人只做第一步。
> 移动文件而不修引用 → 引用完整性门禁变红 → 下一轮的人花时间查一个**并不存在的问题**。


---

> ### ⚠ 第 4 步（代码地图同步）不做 = 完成宣告不成立，该轮计划**不得**归档。
> **这就是为什么代码地图排在归档之前** —— 先验后归档，才不会出现
> 「计划已进冻结容器、仪式却没走完、还不能移回」的死锁。

### 「无变化」也要显式声明

> **本轮无结构变化时，必须显式写一行**：
> 「文件作用清单无需同步（未增删/改名文件，作用无实质变化）」

**为什么**：静默跳过与漏做**同罪** —— 因为**下一轮无法区分「查过没有变化」与「根本没查」**。
这是本框架的一条普遍规律：**没有留痕的「我检查过了」等于没检查**。

## 三、完整档的两步追加 【可选 · 触发：完整档 / 重型档】

### 6. 代码/文件修改记录

与逐轮记录的分工：

| | 逐轮记录章节 | 修改记录 |
|---|---|---|
| 写什么 | **做了什么与为什么**（叙事） | **哪个文件哪一行改成什么、用什么命令验的、退出码多少**（逐文件证据） |
| 关系 | 互补，**不互替** | |

必备节：

- **变更文件表**（文件 / 侧 / 档位 / 为何改，对应步骤号）
- **关键前后片段**（改前/改后，标 `file:line`）
- **验证命令与结果表**（门 / 命令 / 退出码 / 墙钟 / 日志路径 / 关键输出 / 结论）
- **走查两栏**：`静态已验证` 与 `需人工确认（用户回复前不得声明通过）`
- **计划外发现 / 未夹带声明**（本轮**没有**顺手修其他待办覆盖的问题）
- **未完成项与偏差**
- **完成宣告勾选** —— 逐项勾选；本记录不复制清单本体，只记录已勾的步号（清单在当轮计划）

### 7. 收尾快照

无 VCS 时是**必须**的（唯一退路）；有 git 时可选。
快照规格：文件数 + 字节数 + SHA-256 清单，产物落快照目录，**编号回填进当轮记录**。

> **只新增，不覆盖**已有的快照压缩包。覆盖快照 = 毁掉退路。

### 8. 会话交接件 【可选 · 推荐 —— 用户同意才算闭环的一件】

> **这一件不在上面 3/5/7 的步数表里，它是第 8 件独立步骤。**
> **它是推荐项，不是档位默认**（见 `tier-selection.md` §一 与 `mandatory-vs-optional.md` §六）：
> 标准 / 完整 / 重型档都**走三段说明 + 用户表态**，点头才做。用户跳过就记为跳过。
> 轻量档不需要 —— 退化为活跃索引里的「下一步」小节。

生成 `<GOV_ROOT>/登记提示词/提示词-<日期>-<主题>.md`，写**当轮实测**的实态、
下一步、待裁清单、以及上一轮踩过的坑（第四条最贵：不写就永久丢失）。

**它的生成本身零代码改动** —— 否则它描述的实态当场就过时。
**权威派发件 > 交接件**：交接件是执行摘要，冲突以派发件为准。

**为什么单列而不并进 7 步**：步数表按档增减（3/5/7），交接件是按**项目是否需要跨会话**
决定的「推荐项」。混进步数表会让「用户跳过了它」看起来像「仪式少走了一步」。

## 四、走查证据链 【必选 · 触发：有需人工判断的验证】

> **「verdict 经用户确认」那一条不得由执行轮自己打 ✅**，留 ⏳ 直到用户原话确认。

**为什么**：走查证据**从不自证通过**。执行者既生产证据、又裁决证据，等于没有裁决。

配套三条：

1. **任何走查脚本（含临时自制的）都必须产出结构化结果文件**，
   字段含 `verdict: PENDING_HUMAN_REVIEW`、逐条 PASS/FAIL 与计数。
2. **日志条数必须与记录条数逐条核对一致。**
   实测踩过两次：记「21/21」实测 20、记「13/13」实测 14。
   根因都是**只数了关键字面，漏掉「CDP 附着」之类的前置断言**。
3. **「可见」不等于「可点」** —— 落点可达性核验**必须做命中测试**
   （`document.elementFromPoint(x, y)` 落在目标元素**或其子树内**），
   只验可见性会给**假绿**。实测：元素 `getComputedStyle` 一切正常、自动化工具也判定
   `visible, enabled and stable`，但**指针事件被同层的绝对定位元素接走**，
   于是点击 30 秒超时。

## 五、写进生成件的部分

把上面 §二 五步（或按档）**逐字写进规则文档**，并加上这句：

> **第 4 步（代码地图同步）不做 = 完成宣告不成立，该轮计划不得归档。**

以及这句：

> **本轮无结构变化时也必须显式声明一行**，静默跳过与漏做同罪。
