# 文档同步纪律

> 这一节管的不是「写文档」，而是**「让文档保持不撒谎」**。
> 它是整套框架里最不显眼、也最容易整体腐化的一层。

---

## 一、规则载体的多处同步 【必选】

**一条规则若被多个文件承载，改一处必须在同一轮改完全部。**

原项目里有一条规则同时住在 **5 处**：
仓库根的 `AGENTS.md`、规则文档、总表、以及两份模板。

**为什么它每次都腐化**：改的时候只改了「最显眼的那一处」，
下次会话读到没改的那处，**按旧规则执行** —— 而且**这次执行在它自己的眼里完全合规**。

### 通用办法

1. **列出载体清单，写进规则文档本身**（「本条的载体有：…」）。
2. 在规则文档里写明：**任何一轮改动这条规则，必须同轮更新全部载体**。
3. 如果可能，**让其中一处成为权威、其余指向它**（减少载体数量）。
   减不掉的（如宪法必须自包含）就靠清单兜。

> **最坏情况不是漏改，是「漏改的那处看起来更权威」。**
> 宪法最显眼 → 最容易被读 → 最容易被当成唯一真相 → 其他载体腐化了也没人发现。

## 二、计数漂移 【必选】

**任何计数只在一处权威（总表），其他文档引用时指向它。**

- 发现漂移 → **就地更正并在注记区说明**，**不得静默改**。
- 为什么不静默：静默更正让「漂移发生过」这件事不可查，
  于是**同型的漂移会在下一轮再次发生，且没人能看出这是重复**。

---

## 三、静默跳过 = 漏做 【必选】

> **「检查过，没有变化」必须写出来。**

因为**没有留痕的「我检查过了」与「根本没查」在事后完全无法区分**。

典型场景：一轮没有新增/删除文件 → 文件作用清单不需要同步 →
执行者觉得「没必要写」，直接跳过 → 两周后有人问「这轮到底查没查清单」→ **无法回答**。

**纪律**：无变化时也写一行 `本轮无结构变化，<清单>无需同步（原因）`。

---

## 四、行号会漂 【必选】

**引用 `file:line` 前必须实测。**

- 计划件写就之后，代码仍在被并行的编辑推着走 → **普通 `file:line` 会在轮内老化**。
- 实测：一份派发件自曝其引用的行号**整体偏移 +14**（内容全对、行号全偏）。

**三道防线**：

1. 派发件的「执行期第 1 步」= **复核本件全部引用**，偏了几处改几处，逐处留「前 → 后」对照。
2. **引用完整性门禁只验路径存在性，不验内容** —— 它**抓不到行号漂移**。
   这条只能靠纪律兜，**必须在模板这一层写死**。
3. 文档里的行号引用要么带日期戳，要么指向**符号名**而不是行号。

> **实测教训**：一份冻结清单引用的 `src/xxx.ts` **根本不存在**
> （真实定义在另一个文件），而另一个行号引用偏了 10 行。
> **复制一条未经核实的引用，等于传播它。**

## 五、替换前断言唯一命中 【必选】

**做批量替换时，必须先断言目标文本在文件里唯一出现。**

```python
assert text.count(old) == 1, f"命中 {text.count(old)} 处，非唯一"
text = text.replace(old, new)
```

**为什么必须断言而不是「替换全部」**：

- 命中 0 处 → 说明你以为存在的文本不存在（脚本静默跳过 → 你以为改了，其实没改）。
- 命中 ≥2 处 → 你会改掉不该改的地方。

**实测教训**：

- 一次性改 42 处字号时，某个类名**0 命中**（规则体比匹配窗口长）。
  **脚本报错而不是静默跳过** —— 这正是断言的价值。
- 同一条更正**改了两次才对**，因为第一次的判据（「它不带某 CSS 属性」）本身就是错的。

> **规律：批量脚本最危险的失败模式不是"改错"，而是"什么都没改却报告成功"。**
> 断言把「什么都没干」变成一次显式的失败。

## 六、文档结构的机械健全性 【必选】（门禁实现本身可选）

**受治理的文档不得有重复的同一级标题。**

**为什么需要这条**：曾经一轮的编辑脚本里 `indexOf` 未命中，
`slice(0, -1)` **静默截掉末字符而非报错**，于是把整份索引**复制成了两遍**。
而**其余所有门禁没有一道能抓住「文档被复制」** —— 更糟的是，
**复制反而让死链门更绿**（第二份副本被当成了额外的有效命中）。

**重复标题是这种事故最廉价、最可机械判定的指纹。**

**扫描范围要刻意限定**，不要裸扫全仓：

- 纳入：活文档目录 + 每个**闭环落点容器**（计划件在被移走前同样受当轮编辑）+ 宪法文件。
- **排除**：操作记录、归档类目录、素材、问卷、证据目录 ——
  它们**可以有合法的重复标题**（实测：某份报告里 `## 验证输出` 合法出现两次）。
  纳入即误伤。

**牙齿必须验证**：接线当轮临时制造一条重复 → 断言变红且**精确报出文件与行号**。

## 七、跨轮操作的留痕 【必选】

**不属于任何单轮实施计划**的动作 —— 文档体系重组、素材删除、产物迁移、
脚本输出路径变更、`.gitignore` 变更 —— **另建一条记录**：

```
操作记录-<日期>-<主题>.md
```

内容：

- 改前 / 改后的**计数**
- **不可逆删除的 SHA-256 指纹**
- **真实的验证输出**
- **显式列出未完成项**

**记录只追加**：后来的变化写**新的一条**，不改旧的。

> ⚠ 这类操作**不进**「计划内偏差」的计数 —— 两套口径混在一起会互相污染。
> 也不进「跨轮偏差」序列，它有自己的容器。

---

## 八、权威落点 vs. 世界本身 【必选】

**判断「某东西是否存在」时，不要只看文档。**

> 实测错误：因为《接口文档》里没有某接口，就断言「没有任何公开面能做到 X」。
> 错 —— 实测该接口存在且可用。

- 文档是**索引**，不是**世界本身**。
- 判断「**能不能集成**」→ 查文档（这是铁律 2 的判据，文档里没有 = 不许用）。
- 判断「**有没有**」→ 去读**契约源码**。

反向的错同样常见：**把「文档里有」当成「可用」**。
两个方向**同源**，都是把文档当成了世界。

## 九、默认阅读顺序 【必选】

生成件里必须写清：**新会话第一件事读哪几份，按什么顺序。**

**默认阅读顺序的唯一权威是 `<GOV_ROOT>/README.md` §一。**

本文件不复制那份清单 —— 复制即双份。此处只给**原则**：

```
绑定约束（每个会话自动加载）→ 方向（有哪些容器）→ 当前在做什么 → 计数真源 → 按需下钻
```

**为什么它必须写在显眼处**：跨会话最大的损耗是**重新发现上下文**。
一个明确的阅读顺序，把「读 20 份文档」变成「读 4 份，按需再下钻」。
