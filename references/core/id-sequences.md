# ID 序列

> **五套编号并行运行**，**互不替代、互不换算**。前缀可配，不变式不可配。
> **项目自生序列另有登记义务** —— 见 §一·补。

---

## 一、五套序列 【必选】

| 序列 | 记什么 | 起始 | 与轮次的关系 |
|---|---|---|---|
| **`NNN`**（可配前缀，如 `Q-001`） | **队列项**：一个待办 | 001 | 一个队列项可被拆成多轮，**不一一对应** |
| **`ISS-NNN`** | **问题**：一个可核对的缺陷/异常 | 001 | 通常先有问题、后立队列项 |
| **`DEV-NNN`** | **偏差**：实施期与计划不符之处 | 001 | 每轮计划内部另有**计划内偏差**的连续编号，两轨不混 |
| **`OP-NNN`** | **操作**：跨轮的一件动作（单轮实施计划之外的事） | 001 | 一条操作记录可含多个动作，**不一一对应轮次** |
| **轮次号**（如 `R07`） | **一次执行轮** | 按项目定 | 与「逐轮记录」的章节号**一一对应** |

**`OP-NNN` 什么时候用**：任何**不在当轮实施计划内**的动作 —— 文档重组、素材迁移、
脚本输出路径变更、忽略规则变更、以及 `标记删除/` 的**移入 / 还原 / 真删**。
它的权威落点是 `操作记录/`（`完整档起`）。**没有这一套号，跨轮动作无法被精确引用**，
只能写「上一轮那个删除」，下一个会话无从查起。

### 不变式（不可配）

1. **永不复用。** 作废的号不删、不回收、不重新分配。
2. **作废要留号。** 一条被否掉的队列项留在「丢弃」容器里，占着它的号，
   并在总表里写明「已作废 + 原因」。删号 = 让后来的会话误以为这个号空着。
3. **一个号只属于一个东西。** 找不到号的归属时，先查总表，**不要新开一个号**。
4. **计数只认一处。** 「当前开放几个 / 累计完成几个」只在**总表**里写。
   其他文档引用计数时**指向总表**，不各写一份——否则必然漂移。

## 一·补、项目自生序列的登记义务 【必选】

> **框架的五套序列不覆盖项目长出来的新序列。** 不登记 = 撞号，而且撞了没人知道。

**规则**：项目每**新增一种编号序列**（例如 `J-NN` 判据清单、`SPEC-NN`、
按模块前缀的 `WEB-001`），**必须同轮登进 `计划队列/队列总表.md` §一 的编号序列表**，
填齐四列：

| 列 | 填什么 |
|---|---|
| **序列** | 前缀与位数（`J-NN` / `OP-NNN`） |
| **下一个可用 / 已用** | 两个数，与已有序列同列 |
| **真源文件** | **判「这个号有没有被用」时去看的那一个文件**（如 `判据清单.md`） |
| **说明** | 它记什么、与其它序列的关系 |

**真源文件这一列是硬要求。** 没有它，「撞号时去哪查」没有答案 ——
实测某项目 `J-08` 被一轮占用后，下一轮的建议文本仍写「加 J-08」，
因为**没有任何一处能回答「J 的号从哪来」**。

**判据**：项目里出现的每一个 `字母-数字` 形态的编号，
都能在总表 §一 找到对应行。**找不到 = 未登记 = 可撞号。**

**为什么不在 skill 里预定义它们**：新序列是由**项目形态**长出来的（有判据清单才有 `J`），
框架猜不到。所以这里给的是**登记义务**，不是清单本身。

## 二、轮次号：为什么会从「圈号」变成「字母+数字」 【参考 · 历史与教训】

真实历史：项目用了 ①②…㊿ 这 **50 个圈号字符**做轮次号。
**BMP 里没有第 51 个圈号字符** —— 序列用尽了。

当时的裁决（原话）：
> 「圈号内数字如果用尽了就不再使用，新的号码由字母+数字组合来做，和当前已有的号码区分开」

于是新系列 `R<n>`，整数续接 50，首个 `R51`。

**这件事的一般教训**（写进任何新项目的 ID 设计里）：

- **不要用「有尽头的字符集」做无限增长的序列号。** 圈号、罗马数字、单个字母，都会用尽。
- 用尽时的正确处置是**换系列并保持旧号不动**，不是**回收旧号**、也不是**扩码点**
  （扩到补充平面会产生「看起来一样但码点不同」的字符，搜索与比对会静默失效）。
- **判「某号是否被消费」只看权威落点**（逐轮记录里的章节标题），
  **不看全仓原始命中数**。

### 「宣告行」陷阱（实测踩过多次）

在一个大仓库里 `grep` 一个还没被消费的号，会命中**好几处**——
它们全都是**总表里「下一个可用号 = ㊵」这类宣告行**，**没有一处是消费**。

> 实测：某个号在整仓扫出 **7 处命中**，其中「逐轮记录章节标题里含该号」的数目是 **0**。
> 而**只有后者决定任何事**。

**纪律**：

- 判消费，**只看权威落点**（章节标题 / 派发件的「本轮轮次号」字段）。
- **永远不要把圈号一类特殊字符经命令行传参** —— 在 CP936 之类的代码页下会被转坏，
  返回一个**看起来很合理但完全错误**的计数。
  用**码点正则**（`[①-⑳㉑-㉟㊱-㊿]` 这种）扫，不传字面字符。

## 二·补、派发轮与执行轮：**执行轮占新号，派发时预占** 【必选】

> **规则一句话**：**每个执行轮占一个新轮次号**；跨会话派发时，
> **派发那一刻就把执行轮要用的号预占下来**，文件名用预占号，**预占不释放**。

**为什么需要这条**：派发与执行跨会话时，框架原先**两种读法都讲得通**，
于是同一个项目里会长出两种口径（实测：同一项目先后出现「执行占新号」
与「沿用派发号」，直接打破了「章节号与轮次号一一对应」）。
**没有规则 = 每轮自己发明。**

| 时点 | 动作 |
|---|---|
| **派发**（R04，跨会话） | 在派发补充里填**执行轮的预占号**（如 `R05`）；文件名仍用 `<日期>-<轮次号>-<slug>.md`，**其中 `<轮次号>` 填预占号 R05** |
| **执行**（R05） | 直接使用预占号；`项目总结.md` 追加 `## §<章节号> R05 · <主题>` |
| **未能执行就作废** | **号不释放**（与不变式 1 一致）；在总表注记「R05 预占后作废，不回收」 |

**为什么文件名用预占号而不是派发号**：文件名是**执行轮**的标识，
它必须与 `项目总结` 的章节号一致 —— 否则同一轮在两处叫两个号，
而「章节号与轮次号一一对应」正是 id 体系的地基。

**唯一例外：交接件不占号**（`session-handoff.md` §三.2）——
它生成时零代码改动，不构成执行轮。这条已在本文件 §一 的轮次行注明。

**项目若由**其它口径**（如「执行时现取号、派发件只写『待定』」）：
必须在 `项目总结.md` 头部**显式改口径**，并说明章节号与轮次号如何对应。
**默认口径是本节这条** —— 选别的要写理由。

## 三、并行编号的必要性 【参考 · 论证】

**为什么不让五套合成一个号？**

- 一个队列项可以横跨多轮 → 队列号与轮次号**天然多对多**。
- 一个问题可能在登记时还不成计划，只在有实施动作时才派发。
- 偏差分两轨：**计划内偏差**（权威原文在计划文档里）与**框架期偏差**（逐条独立文件）。
  两轨**不混编、不换算** —— 不把后者叫「第 229 条」，也不把前者第 5 条叫 `DEV-005`。

**合一的代价**：所有关系都变成一一对应，任何一对多都得再发明一个副号。
**并行的代价**：文档里必须显式提醒「**这五个号不是一回事**」。
项目里出现过**同一主题同时有两套活跃计划**的冲突，根因正是编号语义没区分开。

## 四、写进生成件的部分

在总表顶部写一段「并行编号表」：

```markdown
## 一、编号序列

> **本表同时是「已登记序列」的名册。** 项目新增任何编号序列，
> **必须同轮加一行**（含「真源文件」列）—— 未登记的序列不受任何唯一性保护。

| 序列 | 当前下一个可用 | 已用 | 真源文件 | 说明 |
|---|---|---|---|---|
| 队列项 | 004 | 3 | 本表 §三 | 永不复用；作废不删号 |
| 问题 | 002 | 1 | `../问题记录/` | |
| 偏差 | 005 | 4 | `../执行偏差/` | 与「计划内偏差」两轨不混 |
| 操作 | 002 | 1 | `../操作记录/` | 完整档起；跨轮动作与 `标记删除/` 的三类动作 |
| 轮次 | R01 | 0 | `../活跃计划/项目总结.md` | 从 R01 起；与逐轮记录的章节号一一对应 |

**本表是优先级的唯一真源。** 发现计数漂移 → **就地更正并在注记区说明**，
不得静默改。其他文档引用计数一律指向本表。
```

**「真源文件」列不能省** —— 它回答「这个号有没有被用，去哪个文件查」。
没有它，撞号时只能全仓 grep，而全仓 grep 会命中宣告行（见 §二「宣告行」陷阱）。

**「发现计数漂移就就地更正并说明」这条必须写进去** ——
否则每个会话都会发现漂移、每个会话都以为「肯定是别人搞错了」、于是没人改，
漂移从一条变成一片。
