## 一、可选容器：由用户选，默认值挂档位

下面四个容器**不是每档都生成**。它们各自解决一类问题，**问题不存在的项目不该有它们** ——
一个长期空置的容器会开始收留不该放的东西。

**判定顺序**：① 按档位取**默认生成集** → ② 尽调中发现触发信号则**改判** →
③ **在生成前把结论告诉用户一句，让他能推翻** → ④ **绝不生成"以防万一"的容器**。

| 容器 | 解决什么 | 触发信号（尽调时看这个） | 默认生成集 |
|---|---|---|---|
| **`证据/`** | 人工/视觉验证的证据往哪放 | 有任何「需要人看才能判断对不对」的东西（UI / 渲染 / 交互 / 音频 / 验收材料） | 标准档起生成；轻量/微型不生成 |
| **`缓存/`** | 生成物不落仓库根 | 门禁/走查会产生日志，或已出现「原文件名不改」的引用需求 | 标准档起生成；轻量视需要 |
| **`工具/`** | 自制门禁脚本的住处与契约集中处 | 项目**没有**现成的门禁脚本位置：查三项 —— ① 无 `scripts/` 目录、② 无 `Makefile` / `package.json` 的 `scripts` 条目、③ 无 CI workflow。**三者同时成立才算触发**；任一存在即视为「已有位置」，不因本条生成（可在门禁表里指向原位） | 完整档起生成；轻量/标准可指向原位 |
| **`快照/`** | 无 VCS 时的唯一退路 | **探 `.git`：缺席就必须生成**，且要进宪法硬停清单 | **条件是"无 VCS"**，与档位无关 |

### 三条纪律

1. **默认值是建议，不是判定**。档位给默认，**用户随时可以推翻** ——
   所以要**先说结论再生成**（「标准档默认带 `证据/` 与 `缓存/`，你要不要？」），
   **不要生成了再问**。
2. **不生成 ≠ 这件事不用管**。例如不生 `证据/`，人工验证的截图仍要**有个地方放** ——
   在尽调结论里写明「证据落 `<已有位置>`」。
   **容器可以省，纪律不能省。**
3. **每个可选容器都带自己的触发信号**（见上表）。
   判断依据是**信号**，不是「高档位就该有」—— 高档位但纯后端的项目，`证据/` 仍是多余的。

### 生成后写进 `<GOV_ROOT>/README.md`

在「容器一览」表里，未生成的容器**不写**；但要在**档位**一节记一句：

```markdown
**可选容器**：本档位默认带 <A/B>；本次**未生成** <C>，原因：<触发信号不成立>。
```

**「本次未生成 X，原因 Y」必须写** —— 否则下一次会话会以为那是遗漏，
然后"好心"把它建起来，收留一堆本该放别处的东西。
