## 一、生成后自检（交付前逐条确认）

交付前逐条确认，任何一条不过就回去补：

- [ ] 门禁表里**没有空行**，每一条要么是真命令，要么是「不适用 + 原因」。
- [ ] 门禁表的**每一行**都填得出三格：**通过写什么 / 失败写什么 / 探测不到写什么**。
      填不出第三格 = 该门禁不完整；**「不适用」与「不可判定」是两件事**，不要混。
- [ ] **每个阻断级门禁都填了自愈出口**（机修 / 手工 / 报告级）；
      填「报告级」的已从阻断清单移除。判据：问「它红了，下一个动作是什么？」——
      答不出、或答案是「再跑一次」= 没填完。
- [ ] 凡**依赖外部数据源**（分页 / 限流 / 窗口 API）的门，都回答了「**末条从哪来**」，
      且终止判据是「本页不满」而不是「本页为空」。
- [ ] **轻量档的裁剪已做过**：不可判定与自愈出口各写一句总规则即可，
      **没有**给轻量档逐行加三格或要求自建修复器。
- [ ] **新增任何计数声明时，同轮登记进受监督集合** ——
      `scripts/selfcheck.py` 的 `CONCEPT_SOURCES`（概念计数：五档之外的
      「N 条提问 / N 条核心约束 / N 条铁律 / N 条共性教训」）或 README 的 artifact 计数。
      未登记的语义计数**不会被自动发现**；叙述性数字不要登记（会淹掉真声明）。
      需要临时豁免时用行内 `<!-- count:off: <原因> -->`，**自检会打印豁免位置**。
- [ ] **每条 anti-pattern 都有 `固化：` 行**，取值六选一：
      `gate:<自检门>` / `contract:<路径>§<节>` / `template:<路径>` /
      `discipline:<路径>§<节>` / `manual(<原因>)` / `none(<原因>)`。
      `none` 合法且被鼓励 —— **承认缺口比假装覆盖好**。
- [ ] 宪法段写进了**宿主真正会自动加载的那个文件**，且**没有覆盖**既有内容。
      **宿主相关**：Claude Code 读 `CLAUDE.md`（`AGENTS.md` 需 `@AGENTS.md` 导入）；
      多数其他 agent 读 `AGENTS.md`。**目标项目会用哪个宿主，就核对哪个。**
      核对：打开那个文件，能看见宪法段正文或指向它的导入行。
      写进 `AGENTS.md` 但没在 `CLAUDE.md` 里导入 = **Claude Code 下从未被读过**。
- [ ] 无 VCS 的项目，硬停清单里有「快照是唯一退路」，且快照命令可执行。
- [ ] **本档位要求的** ID 序列的「下一个可用号」都在总表里写明，且起始值不是随便写的
      （轻量：队列 + 轮次；标准：+ 问题；完整 / 重型：+ 偏差）。
- [ ] 「哪些目录绝对不许改」有明确答案，并落进了可写范围表。
- [ ] 每个生成的文档里，**没有本机专属的事实**（路径、端口、用户名、代理）——那些属于项目，不属于框架。
      **例外一：逐字记录的用户原话**。`authorization-state-machine.md` 要求原话逐字落档，
      而原话里可能含绝对路径。此时**保留原话、把路径段脱敏**（`<本机路径>`），
      并在原话后注明「**路径已脱敏**：本机事实不进生成件」。
      **例外二：`工作范式.md` §六「环境事实」（推荐项）与尽调结论里的探测证据**。
      前者**本来就是本机实测事实**，写进生成件正是它的目的；后者是「命令 + 输出」的证据，
      脱敏后就无法复查「当初是不是探错了」。
      **判据**：脱敏后仍然能看出用户当时要什么 / 当初实测到了什么；看不出 = 脱敏过度。
      **例外二只豁免这两个落点** —— 别处的端口、绝对路径、用户名仍然禁止。
- [ ] `<GOV_ROOT>/README.md` 写清了**默认阅读顺序**（新会话第一件事读哪几份、按什么顺序）。
- [ ] 档位写进了 `README.md`，**含「为什么不选更高档」**与**双向**升降档信号。
- [ ] **判出微型档时没有生成 `<GOV_ROOT>/`** —— 而是给了 `NEXT.md` 与「为什么不装」的说明。
- [ ] 判出重型档时，**角色与权限矩阵 / 不可变台账 / 发布纪律**三者都到位。
- [ ] 交付件说明了**怎么升档**与**怎么降档**（降档 = 标注暂停使用，**不是删文件**）。
- [ ] **`工作范式.md` 生成了** —— 它是规则的权威载体；只给宪法段不给全文，细则无处可查。
- [ ] **每个生成的容器都有一份 `README.md`**，写清「放什么 / 怎么进 / 怎么出 / **不在这里放什么**」。
- [ ] **`活跃计划/README.md` 存在**，且含「最近 N 轮」与「代码地图三节」两处落点
      —— 否则完成宣告第 3 步与第 4 步无处可落。
- [ ] 模板里**没有留下永远不会被填的占位符**；用不上的节**删掉**而不是留空。
- [ ] 需要但暂缺的门禁脚本，门禁表里写的是 **「待实现 + 重建入口」**，
      **不是一个不存在的命令**。
      「重建入口」指目标项目里的落点（如 `<GOV_ROOT>/工具/README.md` 的索引行）——
      **不得写本 skill 内部路径**（见本节倒数第 4 条）。
- [ ] **每个「有归档落点」的容器都配了归档子目录** ——
      问题 → `问题归档/`、偏差 → `偏差归档/`。**归档子目录是冻结的**，
      且与源容器**不重叠、不留副本**（源容器 = 未闭环的，归档 = 已闭环的）。
- [ ] **可选容器（证据 / 缓存 / 工具 / 快照）逐个按触发信号判过**，
      且**生成前把结论说过一遍**让用户能推翻；未生成的写明了「原因」。
- [ ] **不生成的可选容器，其纪律仍有着落**（如证据落哪个已有位置），
      写进了尽调结论 —— **容器可以省，纪律不能省**。
- [ ] **必选集（`mandatory-vs-optional.md` §二）一条不少** —— 不因项目小、档位低而省略。
- [ ] **「推荐」项在初始化前逐条说明了理由**，且**三段都讲全了**：
      **① 为什么推荐 ② 成本影响 ③ 不做的后果** —— 缺一段就是没说明白。
      **每段都落到了可比较的量上**（时间 / 频率 / 文件数 / 依赖）。
      用户同意的写了、跳过的也在 `README.md` 记了一行 —— **不是生成完再问**。
- [ ] **可选规则逐条按「主题物是否存在」判过**（§三），
      未纳入的在 `<GOV_ROOT>/README.md` 写明了「哪些未纳入 + 原因」。
      **判据是主题物，不是项目规模** —— 「项目小所以不做文档纪律」是错的。
- [ ] **完成宣告的步号逐处人工核对** —— `ordinal-consistency` 只抓「步号旁边就有主题词」
      的写法；**目录树、索引里的纯引用行（如「某模板 ← 第 3、4 步的落点」）它看不见**。
      全文搜 `第\s*\d+\s*[、，/]\s*\d+\s*步` 与 `第 \d+ 步`，逐个对照 `completion-ritual.md` §一。
- [ ] **产物里没有 skill 内部路径**（`references/` / `templates/` / 字面量 `<GOV_ROOT>`）。
      **这一项机器扫不到** —— `template-dead-links` 只扫模板的生成块，
      扫不到生成者手写的产物。**端到端试跑实测踩到过**。
      核对方法：`grep -rn "references/\|templates/\|<GOV_ROOT>" <GOV_ROOT>/`
- [ ] **容器集合 ⊆ 档位允许集合**。对照 `references/gen-tree.md` 的档位标记，
      确认**没有多建**属于更高档位的容器（例：标准档不得有 `丢弃计划/`）。
      **实测教训**：旧版生成树没标档位，标准档被误生成了三个不该有的容器。
- [ ] **必选集（四条核心约束 + 默认阅读顺序 + 静默跳过=漏做 + 权威落点）一条不少。**
