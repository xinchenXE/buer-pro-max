# 会话交接（跨会话不失忆） 【可选 · 推荐 —— 初始化前向用户说明理由，用户定】

> **本项是「推荐」不是「必选」**：只在**跨会话**的项目里才划算。
> 初始化前需按 `mandatory-vs-optional.md` §六 的三段格式说明：
> **① 为什么推荐（防什么）② 成本影响 ③ 不做的后果** —— 用户点头才做。
>
> 这套框架里**最容易被忽略、收益最高**的机制。
> 它解决的问题是：**下一次会话打开这个项目时，凭什么知道上一轮发生了什么、下一步该做什么。**

---

## 一、为什么需要它

跨会话的损耗**不体现在「不知道代码长什么样」**——
代码在那儿，读就是了。损耗体现在**四件只有当事人知道的事**：

1. **上一轮**改了什么、为什么改（记录里有，但埋在一堆文档里）
2. **现在**卡在哪（哪些门没绿、哪些裁决还没下来）
3. **下一步**该做什么（活跃计划里有，但要先找到它）
4. **别踩哪些坑**（上一轮刚踩过，但没写下来就永久丢失）

第 4 条最重要：**踩过的坑如果不写，下一个会话会一模一样地再踩一遍**，
而且它踩的时候**完全不知道自己在重复**。

---

## 二、交接件的形态

它**不是**「工作总结」。它是一份**指令**——写给下一个会话，告诉它从哪开始。

存放位置：`<GOV_ROOT>/登记提示词/提示词-<日期>-<主题>.md`
（名字不重要，重要的是它**在显眼处、按日期排列**。）

### 必含的节

```markdown
# 提示词 · 会话交接：<本轮主题> ＋ 当前实态与待裁清单

> **交接对象**：下一个会话。
> **你手上没有未收口的活** —— 上一会话（本会话）已完成 <X>，**门禁全绿、工作区干净**。
> **权威派发件（必读，本提示词是执行摘要，冲突以派发件为准）**：<路径>
> **生成**：<日期>（**生成方本轮只写文档，零产品代码改动**）

## 〇、先读这四条（别跳，它们决定你从哪开始）

2. <一条会影响你看到的一切的前提，例如「上一会话刚改过全站字号，既有截图全是改前的」>。
3. **有一条我犯过的错，写在下面了**，别重踩（见 §教训）。
```

## 三、三条写法纪律

### 1. 「实态」必须是**实测值**，不是复述

交接件里所有计数、基线、行号，都必须是**生成当轮实测的**，并带日期。
复述上一轮的数字化 = 把漂移传递下去。

### 2. 交接件**只写文档，零代码改动**

它的生成**本身就是一轮**（但不占轮次号），产物只有这一份文件。
**为什么**：如果写交接件时顺手改了代码，交接件描述的实态**当场就过时了**。

### 3. **权威派发件 > 交接件**

交接件是**执行摘要**。冲突时以派发件为准，并在文件头写死这句话。
**为什么**：摘要在概括时会丢限定条件（老问题）。写明优先级，执行者才知道该信谁。

---

## 四、和闭环仪式的关系

交接件是**闭环的第 8 件**（推荐项，标准起适用），在五步/七步之外。

顺序：

```
完成宣告 N 步走完
  → 生成交接件（当轮实态 + 下一步 + 待裁清单）
    → 向用户报告
```

**与「逐轮记录」的分工**：

| | 逐轮记录章节 | 交接件 |
|---|---|---|
| 面向 | **历史**（这一轮做了什么） | **未来**（下一个会话该做什么） |
| 语气 | 陈述 | **指令** |
| 是否改写 | 冻结 | 每轮新写一份（旧的留着） |

两者**不互替**：逐轮记录说「我做了什么」，交接件说「你该做什么」。

---

## 五、生成时的落地

1. 在 `<GOV_ROOT>/` 下建 `登记提示词/` 容器，放一份 `_交接件模板.md`。
2. 在规则文档的闭环仪式一节里，把「生成交接件」列为**第 8 件**（推荐项：标准起适用，用户点头才做）。
3. 在索引的「默认阅读顺序」里说明：**新会话读到的第一份活文档，通常是最近的一份交接件。**

---

## 六、什么时候不用它

- **轻量档**：单会话能做完一件的项目，交接件的成本大于收益。
  → 改为在活跃计划索引里维护一个「下一步」小节。
- **单人单次实验**：不需要。
- **有完整 issue tracker + 每轮都有人写 PR 描述**的项目：
  交接件的内容已经被 PR 覆盖了 → 不要重复一套。

> 判断口径：**如果「下一个会话要花多久才能知道你上一次干到哪」这个问题有现成的答案，
> 就不需要交接件。** 没有，就需要。
