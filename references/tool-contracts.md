# 工具契约（门禁脚本怎么实现）

> 本 skill **不打包脚本**（见 `README.md` §五 取舍 1）。
> 但有两道**语言无关的元门禁**值得任何项目都上，还有一支快照工具是**无 VCS 时的唯一退路**。
> 这里给的是**契约** —— 扫什么、判据是什么、日志落哪、怎么验证它有牙齿。
> **实现由目标项目自己做。**

---

## 一、文档基线同步（`docsync-check` 型）

> **本节与后面几节都有 `### 解决什么` / `### 契约` 这类同名三级标题。**
> 这是**跨契约的合法复用**，不是「文件被复制」。
> 因此若目标项目上「重复标题门」，**必须把 `references/` 排除在扫描面之外** ——
> 重复标题在这个目录里是结构，不是事故指纹（详见 `anti-patterns.md` #16 与本文 §一 的口径）。

### 解决什么

治理文档里写着一堆**文件计数**（「分类A 69 / 分类B 53 / tests 99 / …」）。
加了文件没更新数字 → 数字开始说谎 → 而**没有任何一道别的门禁能发现**。

### 契约

```text
输入：
  - 一组「分类 → 判据」：分类名 + 匹配的文件 glob/正则
  - 一处「基线常量」：分类名 → 期望值

行为：
  1. 按判据实际统计每类的文件数
  2. 与基线常量逐一比对
  3. 任一不符 → 打印「分类：期望 X / 实际 Y」，退出码非零
  4. 全部相符 → 打印六项实测值，退出码 0
  5. 取数失败（目录不可读 / 统计命令超时）→ 计入 undecidable，**不得用 0 冒充真值**

输出必须含：measured=<N> undecidable=<N>（undecidable>0 不阻断，但必须播报）

附加自检（强烈建议）：
  6. 扫描受治理文档，报告**重复的 `## ` 标题**（见下「为什么」）
```

### 关键设计

**基线常量只能有一处。** 写在脚本里的一个对象，或一个 sidecar 文件；
规则文档**引用它**，不另写一份。两处各写一份 → 必然分叉。

### 为什么加「重复标题」这一条

> 实测事故：一轮的编辑脚本里 `indexOf` 未命中，`slice(0, -1)` **静默截掉末字符而非报错**，
> 于是把整份索引**复制成了两遍**。
> **其余所有门禁没有一道能抓住「文档被复制」** —— 更糟的是，
> **复制反而让死链门更绿**（第二份副本被当成了额外的有效命中）。

重复的同一级标题是这种事故**最廉价、最可机械判定**的指纹。

**扫描范围要刻意限定**，不要裸扫全仓：

| | 范围 |
|---|---|
| **纳入** | 活文档目录 + **每个闭环落点容器**（计划件在被移走前同样受当轮编辑）+ 宪法文件 |
| **排除** | 操作记录、归档类目录、素材、问卷、证据目录 |

**为什么排除**：它们**可以有合法的重复标题**
（实测：某份报告里 `## 验证输出` 合法出现两次）。纳入即误伤。

### 牙齿验证

见文末「牙齿验证（所有契约共用）」。

## 二、引用完整性（`ref-check` 型）

### 解决什么

治理文档之间互相引用。文件被移动/改名后，引用变成死链，
**而没人会去逐个点开检查**。

### 契约

```text
输入：
  - 扫描面：活文档（live）/ 冻结文档（frozen）两组
  - 一份允许清单（allow list）：已知的历史遗留死链

行为：
  1. 提取每个文档里的路径引用与文档间链接
  2. 逐个判断目标是否存在
  3. 不存在的 → 计数；若在允许清单里 → 计入 allowEntries
  4. 输出 dead=N / allowEntries=N / docs=N / skippedSuppressed=N
  5. dead > 0 → 退出码非零
  6. **docs=0（一个可扫文档都没找到）→ 退出码非零** —— 「查了 0 个」不等于「0 个坏的」
  7. 文件存在但读不出（锁定 / 编码错误）→ 计入 undecidable 并播报

抑制机制（**必须**）：
  - 块级：<!-- ref-check:off --> … <!-- ref-check:on -->
  - 行级：行末 <!-- noref -->
  - **打印被抑制的条数**（skippedSuppressed=N）
```

### 三个关键设计

**1. live / frozen 必须分开。**

- **live**：活文档，死链即红。
- **frozen**：冻结的历史面，死链**只报告不拦** ——
  它们是账本的一部分，**不要去"修好"它们**。

**2. 抑制机制必须打印计数。**

否则抑制标记会变成藏污纳垢的地方。`skippedSuppressed=N` 让「被藏起来的」可见。

**3. 不得为了让门变绿而加豁免行。**

豁免行只应记录**已知的、有理由的**历史遗留，且**只增不减地讨论**。
**正确处置是当轮修好自己的引用。**

### 最大的陷阱

> **任何「报告某路径已死」的文档，本身会被当成新的死链。**

那篇文章里的死链字符串会被扫描器当成一个真实引用。
**必须用抑制标记包住它。**
实测：同一个坑**在一轮里连续踩了三次**。

### 局限（必须写进文档）

**引用完整性只验路径的存在性，不验内容。**
它**抓不到行号漂移** —— 一个指向 `file.ts:161` 的引用，即使真实位置已漂到 `:171`，
只要文件存在就通过。
**这条只能靠纪律兜**（见 `doc-sync-discipline.md` §四）。

配套的**行号引用扫描门**（本 skill 的 `scripts/selfcheck.py` 里叫 `line-number-refs`）
覆盖范围同样有限，必须在文档里写明，否则读者会以为它全查了：

- 只认 `*.md:NNN` 与 `（LNN）` / `（LNN–LNN）` 两种形态，**且 `L` 后至少两位数字** ——
  裸层名 `（L1）` 不算行号（否则任何写「L1/L2」的文档都会误红）；
- **不覆盖代码文件**（`file.ts:161`、`selfcheck.py:88`）—— 代码行号靠纪律，不靠门。

## 三、快照（无 VCS 时的唯一退路）

### 什么时候必需

**目标项目没有 VCS**，或治理根不在仓库内。
此时快照是「全量替换类改动」出错后的**唯一回滚手段**。

有 git 时它是**可选**的补充（用于跨会话比对工作区变化）。

### 契约

```text
输入：
  - Label：本次快照的标识
  - Zip：是否同时打压缩包
  - Baseline（可选）：上一份 manifest，用于输出 changed 文件清单

行为：
  1. 遍历范围（排除 node_modules / 构建产物 / 大体积证据目录）
  2. 对每个文件记 SHA-256 + 字节数
  3. 写 manifest：`snap-<日期>-<label>.manifest.tsv`（+ `.meta.json`；带 `-Baseline` 时另出 `.diff.tsv`）
  4. 若有 Baseline → 输出 added / removed / changed 三组清单
  5. 产物落快照目录，**只新增，不覆盖**

输出摘要：
  files=<N> bytes=<N> sha256-manifest=<路径>
```

**完整产物表**（四个文件的字段含义）见 `templates/_快照README模板.md` §一 —— 那是对外可读的版本，本节是契约。

### 三条纪律

1. **只新增，不覆盖任何已有快照。** 覆盖快照 = 毁掉退路。
2. **快照编号在收尾时回填**进当轮记录（编号晚于快照是正常的）。
3. **它不是 git tag** —— 无 VCS 时没有 tag 可打，manifest 是替代品。

### 用 manifest 算「工作区是否干净」

无 VCS 时没有 `git status`。用 `snapshot -Baseline <上一份 manifest>` 得到
added/removed/changed 三组清单，**这就是脏度度量**。

**产物落点**：`<GOV_ROOT>/快照/`（**无 VCS 时唯一退路**；有 git 时此目录可不要）。
**`.diff` / `.patch` / `.orig` / `.rej` / `.bak` 一律落缓存目录**，不进治理目录。

## 四、走查证据包装（有人工验收时）

### 契约

```text
输入：走查脚本路径 + Label

行为：
  1. 跑脚本
  2. 在证据目录写 walk-audit-<时间戳>-<label>.json：
       { verdict: "PENDING_HUMAN_REVIEW",
         items: [ { name, status: PASS|FAIL|UNDECIDABLE, detail } ],
         counts: { pass, fail, undecidable } }
  3. 日志落缓存目录
  4. 无显示环境 / 脚本无法启动 → 全部条目记 UNDECIDABLE，
     **不得写空 items 后当 PASS**（0 条证据 ≠ 全部通过）
```

### 三条纪律

1. **`verdict` 初始必须是 `PENDING_HUMAN_REVIEW`，且不得由执行轮自己改成 PASS。**
   执行者既生产证据、又裁决证据 = 没有裁决。（`anti-patterns.md` #1）
2. **记录里的条数必须与日志逐条核对一致。**
   实测踩过两次：记「21/21」实测 **20**、记「13/13」实测 **14**。
   根因都是**只数了关键字面，漏掉「CDP 附着」之类的前置断言**。
   **计数从日志机械抽取，不手写。**
3. **任何走查脚本（含临时自制的）都必须产这个包装文件** ——
   「自制脚本直跑」不是豁免理由。

## 五、给生成件的建议

生成时在门禁表里这样写：

| 门 | 命令 | 状态 |
|---|---|---|
| 文档基线同步 | `node <脚本路径>` | <已有 / **待实现（契约见本文档）**> |
| 引用完整性 | `<命令>` | <已有 / **待实现**> |
| 快照 | `<命令>` | <已有 / **待实现**；本项目<有/无> VCS> |

**「待实现」是诚实的写法。** 不要写一个不存在的命令 ——
那会让门禁名存实亡，而且**没人会发现**（因为没人在跑它）。

## 六、自愈出口契约（每个阻断门都要回答）

> **本节是契约，不打包任何脚本。** 它只要求目标项目在门禁表里写清「红了谁修」；
> 修复器本身由目标项目自己实现，**不在本 skill 里发布**（见文首「本 skill 不打包脚本」）。

### 为什么需要它

一道**恒红的阻断门**等于治理体系的空转开关：整轮「应用失败 → 回滚」之后，
没人知道下一步该改哪里。而「再跑一次」不是修复 —— 它只是把同一个红再走一遍。

### 三条契约

1. **同源**：检测谓词与修复谓词必须来自**同一份**常量 / 正则 / 基线表。
   各写一份 → 要么「检出但不修」恒红，要么修复方向与检测相反。
2. **保守**：修复器只改**归属唯一**的条目。
   命中 0 处或 ≥2 处 → **只报告，不改写**（猜归属会改错正确的内容）。
3. **可演练**：必须支持 `--dry-run`（只报告将改什么），
   且**被跳过 / 被抑制的条数必须打印** —— 否则抑制标记会变成藏污纳垢处。

### 顺序

**机修先于校验**（`修 → 验`）。反过来做，永远差一步。

### 机修与手工都没有时

**降为报告级，不挂阻断。** 注意顺序：**先看手工出口** —— 类型检查、单测、构建这类门
 通常没有机修命令，但有明确的手工修复步骤，**它们仍然是阻断门**。
 只有「机修写不出、手工也写不出可执行步骤」的检查项才降级 ——
 把修不了的东西挂在阻断位上，等于让整条链路永久红灯。
 门禁表里写 `报告级`（见 `core/gates-and-holds.md` §一）。

### 验收

随便挑一个阻断门，回答：「它红了，下一个动作是什么？」
答得出来、且不是「再跑一次」→ 这一行填完了。答不出来 → 它应该降为报告级。

## 牙齿验证（所有契约共用）

**每一道门接线当轮都要做一次牙齿验证**：临时制造一条它本该抓到的违规 →
断言它**变红**，且**精确报出位置**（文件 + 行号/条目）→ 还原。

> **没见过它变红的门，等于没有门。**
> 你只知道它不报错，不知道它会报错 —— 而后者才是门存在的意义。

### 三态验证（有修复器时）

只做「造违规 → 变红」是**单侧**验证，会漏掉「**范围过宽 = 假绿**」：
判据切片没剥离注释行，而注释里恰好含被检查的字符串 → 注入缺陷**竟未检出**。

| 态 | 制造什么 | 期望 |
|---|---|---|
| ① **注入** | 一条真违规 | 变红，且**精确报出位置** |
| ② **换写法** | 同一违规换个措辞 / 标点 / 位置 | **仍然变红**（防止判据只认一种字面） |
| ③ **修复态** | 已修好的输入 | **零漂移**：退出码 0，且**不误报** |

> **没有修复器时**，第 ③ 态记「不适用 + 原因」，**不得省略**（静默跳过 = 漏做）。
> 「修好了」必须由**独立**于修复器的手段确认 —— 用修复器自己验证自己，等于没验。

**逐门验证清单**（做法相同，违规不同）：

| 门 | ① 注入什么 | ② 换个什么写法 | ③ 修复态检查 |
|---|---|---|---|
| 文档基线同步 | 加一个源文件但不动基线常量 | 换个目录放同样的文件 / 改文件名大小写 | 基线回填后 `measured` 全相符 |
| 引用完整性 | 写一个指向不存在路径的引用 | 用行内代码包住死链 / 换相对路径写法 | 删掉死链后 `dead=0` |
| 快照 | 对已有快照再打一次同名快照 | 换 label 大小写再打一次 | 只新增不覆盖 |
| 走查证据包装 | 让 `verdict` 由执行轮自己改成 PASS | 改成别的等价绿值 | 初始仍为 `PENDING_HUMAN_REVIEW` |
| 自愈出口（§六） | 让修复器改一个归属不唯一的条目 | 让它命中 0 处 | 修复后检测门变绿，且非目标项未变 |

**记录方式**：把每次验证的「制造了什么 / 报了什么 / 是否精确 / 修复态是否零漂移」
写进当轮记录。**没留痕的牙齿验证等于没做**（本框架的普遍规律）。
