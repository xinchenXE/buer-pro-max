# 工具契约（门禁脚本怎么实现）

> 本 skill **不打包脚本**（见 `README.md` §五 取舍 1）。
> 但有两道**语言无关的元门禁**值得任何项目都上，还有一支快照工具是**无 VCS 时的唯一退路**。
> 这里给的是**契约** —— 扫什么、判据是什么、日志落哪、怎么验证它有牙齿。
> **实现由目标项目自己做。**

---

## 一、文档基线同步（`docsync-check` 型）

> **本节与后面几节都有 `### 解决什么` / `### 契约` 这类同名三级标题。**
> 这是**跨契约的合法复用**，不是「文件被复制」。
> 因此若目标项目上「重复标题门」，**必须把 `references/` 排除在扫描面之外** ——
> 重复标题在这个目录里是结构，不是事故指纹（详见 `anti-patterns.md` #16 与本文 §一 的口径）。

### 解决什么

治理文档里写着一堆**文件计数**（「分类A 69 / 分类B 53 / tests 99 / …」）。
加了文件没更新数字 → 数字开始说谎 → 而**没有任何一道别的门禁能发现**。

### 契约

```text
输入：
  - 一组「分类 → 判据」：分类名 + 匹配的文件 glob/正则
  - 一处「基线常量」：分类名 → 期望值

行为：
  1. 按判据实际统计每类的文件数
  2. 与基线常量逐一比对
  3. 任一不符 → 打印「分类：期望 X / 实际 Y」，退出码非零
  4. 全部相符 → 打印六项实测值，退出码 0
  5. 取数失败（目录不可读 / 统计命令超时）→ 计入 undecidable，**不得用 0 冒充真值**

输出必须含：measured=<N> undecidable=<N>（undecidable>0 不阻断，但必须播报）

附加自检（强烈建议）：
  6. 扫描受治理文档，报告**重复的 `## ` 标题**（见下「为什么」）
```

### 关键设计

**基线常量只能有一处。** 写在脚本里的一个对象，或一个 sidecar 文件；
规则文档**引用它**，不另写一份。两处各写一份 → 必然分叉。

### 扫描面默认排除（**所有元门禁共用**）

> 每道元门禁（基线 / 引用 / 重复标题 / 覆盖自检）都要有自己的扫描面。
> **下面四项默认排除**，除非有明确理由纳入 —— 并且排除项必须写进脚本常量，
> 不能只留在文档里。

| 排除 | 为什么 |
|---|---|
| `.git/` `node_modules/` `venv/` `__pycache__/` | 不是内容，且会让计数在全新克隆与本地之间不同 |
| **`缓存/`**（含一次性脚本、日志、diff） | 生成物。计进去会让基线每轮乱跳 |
| **`标记删除/`**（若启用） | **候删件不是活文档**。它在等待用户裁决，不应被要求「被引用」或计入基线 |
| **`快照/`**（若启用） | 历史全量副本。纳入会让基线随快照数量增长 |

> **为什么写进契约而不是容器模板**：容器模板只管「这个容器怎么用」；
> **扫描面是所有门禁的共同默认值**，散在五个模板里必然漏掉一个。
> 实测：新加 `标记删除/` 时，容器模板写了「门禁必须排除本容器」，
> 但契约正文没有 —— 于是照契约实现的门禁**默认会把候删件当活文档**。

**判据**：随便挑一道本项目自制的元门禁，问「它的扫描面排除哪几项？」
答不出、或答得与上表不一致 → 这一条没落地。

### 为什么加「重复标题」这一条

> 实测事故：一轮的编辑脚本里 `indexOf` 未命中，`slice(0, -1)` **静默截掉末字符而非报错**，
> 于是把整份索引**复制成了两遍**。
> **其余所有门禁没有一道能抓住「文档被复制」** —— 更糟的是，
> **复制反而让死链门更绿**（第二份副本被当成了额外的有效命中）。

重复的同一级标题是这种事故**最廉价、最可机械判定**的指纹。

**扫描范围要刻意限定**，不要裸扫全仓：

| | 范围 |
|---|---|
| **纳入** | 活文档目录 + **每个闭环落点容器**（计划件在被移走前同样受当轮编辑）+ 宪法文件 |
| **排除** | 操作记录、归档类目录、素材、问卷、证据目录 |

**为什么排除**：它们**可以有合法的重复标题**
（实测：某份报告里 `## 验证输出` 合法出现两次）。纳入即误伤。

### 断言设计禁忌 【必选 · 触发：项目自制计数或编号断言时】

> **这一节的三个坑，都会让「合法状态」被自己的门禁判红。**
> 它们比假绿更难发现：假绿是「没查出来」，假红是「查错了」，
> 而执行者面对假红会去**改数据**，把正确的东西改坏。

#### ① 计数必须「归档感知」——递归，且口径写死

治下容器里**有归档子目录**（`问题记录/问题归档/`、`执行偏差/偏差归档/`）。
「这个容器有几个文件」因此有**两个都正确**的答案：直属 N 个、递归 N+M 个。

- **规则**：任何计数断言**必须递归**（把归档子目录算上），
  因为配置项与实际文件是**移动关系** —— 不递归时，每关闭一条记录，计数就掉 1，
  而总数并没有变。
- **规则**：口径必须写在脚本里**同一行**（递归 / 非递归、排除哪些模式），
  不许留给人猜。实测教训：「数字对不上」的下一轮往往不是数据错，是**口径换了一次**。

> **陷阱**：`self-check.md` 里那条「清理/验证的完备性」（`mandatory-vs-optional.md` #23）
> 讲的是**扫描面**要递归；这里讲的是**计数口径**要递归。两者容易混成一条。

#### ② 业务计数不得等于文件数

「开放 ISS 数」「开放 DEV 数」是**业务状态**，不是文件数。
它们必须按**状态字段**统计（`状态：开放`），**不得**用「目录里有几个文件」来代替。

**为什么**：一条已关闭但尚未移动的 ISS，状态是「已关闭」；文件数却仍然算它。
用文件数冒充业务计数，会在「关闭流程走到一半」时必然算错 ——
而那正是关闭流程**唯一需要它准确**的时刻。

#### ③ 编号断言：按「全局序列 / 文档内编号」分开说

**不能一刀切说「编号不查连续性」** —— 那会反向破坏合法的连续编号。

| 类型 | 例子 | 连续性断言 | 唯一性断言 |
|---|---|---|---|
| **全局序列**（永不复用、作废留号） | `ISS-NNN` / `DEV-NNN` / `OP-NNN` / 队列项 / 轮次号 | ❌ **禁止** | ✅ 必须 |
| **文档内编号**（一个文件内部的条目） | 计划内的「偏差记录」1..N；`判据清单.md` 的 `J-NN` | ✅ **合法且推荐** | ✅ 必须 |

**为什么全局序列不能查连续**：作废留号是**设计意图**（`id-sequences.md` §一 不变式 2）。
一张作废的号永远不回来，所以序列**必然**跳号。查连续 = 把正确状态判红，
而且执行者唯一的「修复」办法是**回收号** —— 直接违反不可配的不变式。

**唯一性怎么查**：判「某号是否被消费」只看**权威落点**
（`id-sequences.md` §二「宣告行」陷阱），不要在全仓裸 grep 命中数。

### 牙齿验证

见文末「牙齿验证（所有契约共用）」。这三条禁忌的验证方式是**反向**的：
按禁忌写一个断言 → 制造一个合法状态 → **它必须不报红**（否则就是假红）。

## 二、引用完整性（`ref-check` 型）

### 解决什么

治理文档之间互相引用。文件被移动/改名后，引用变成死链，
**而没人会去逐个点开检查**。

### 契约

```text
输入：
  - 扫描面：活文档（live）/ 冻结文档（frozen）两组
  - 一份允许清单（allow list）：已知的历史遗留死链

行为：
  1. 提取每个文档里的路径引用与文档间链接
  2. 逐个判断目标是否存在
  3. 不存在的 → 计数；若在允许清单里 → 计入 allowEntries
  4. 输出 dead=N / allowEntries=N / docs=N / skippedSuppressed=N
  5. dead > 0 → 退出码非零
  6. **docs=0（一个可扫文档都没找到）→ 退出码非零** —— 「查了 0 个」不等于「0 个坏的」
  7. 文件存在但读不出（锁定 / 编码错误）→ 计入 undecidable 并播报

抑制机制（**必须**）：
  - 块级：<!-- ref-check:off --> … <!-- ref-check:on -->
  - 行级：行末 <!-- noref -->
  - **打印被抑制的条数**（skippedSuppressed=N）
```

### 三个关键设计

**1. live / frozen 必须分开。**

- **live**：活文档，死链即红。
- **frozen**：冻结的历史面，死链**只报告不拦** ——
  它们是账本的一部分，**不要去"修好"它们**。

**2. 抑制机制必须打印计数。**

否则抑制标记会变成藏污纳垢的地方。`skippedSuppressed=N` 让「被藏起来的」可见。

**3. 不得为了让门变绿而加豁免行。**

豁免行只应记录**已知的、有理由的**历史遗留，且**只增不减地讨论**。
**正确处置是当轮修好自己的引用。**

### 最大的陷阱

> **任何「报告某路径已死」的文档，本身会被当成新的死链。**

那篇文章里的死链字符串会被扫描器当成一个真实引用。
**必须用抑制标记包住它。**
实测：同一个坑**在一轮里连续踩了三次**。

### 局限（必须写进文档）

**引用完整性只验路径的存在性，不验内容。**
它**抓不到行号漂移** —— 一个指向 `file.ts:161` 的引用，即使真实位置已漂到 `:171`，
只要文件存在就通过。
**这条只能靠纪律兜**（见 `doc-sync-discipline.md` §四）。

配套的**行号引用扫描门**（本 skill 的 `scripts/selfcheck.py` 里叫 `line-number-refs`）
覆盖范围同样有限，必须在文档里写明，否则读者会以为它全查了：

- 只认 `*.md:NNN` 与 `（LNN）` / `（LNN–LNN）` 两种形态，**且 `L` 后至少两位数字** ——
  裸层名 `（L1）` 不算行号（否则任何写「L1/L2」的文档都会误红）；
- **不覆盖代码文件**（`file.ts:161`、`selfcheck.py:88`）—— 代码行号靠纪律，不靠门。

## 三、快照（无 VCS 时的唯一退路）

### 什么时候必需

**目标项目没有 VCS**，或治理根不在仓库内。
此时快照是「全量替换类改动」出错后的**唯一回滚手段**。

有 git 时它是**可选**的补充（用于跨会话比对工作区变化）。

### 契约

```text
输入：
  - Label：本次快照的标识
  - Zip：是否同时打压缩包
  - Baseline（可选）：上一份 manifest，用于输出 changed 文件清单

行为：
  1. 遍历范围（排除 node_modules / 构建产物 / 大体积证据目录）
  2. 对每个文件记 SHA-256 + 字节数
  3. 写 manifest：`snap-<日期>-<label>.manifest.tsv`（+ `.meta.json`；带 `-Baseline` 时另出 `.diff.tsv`）
  4. 若有 Baseline → 输出 added / removed / changed 三组清单
  5. 产物落快照目录，**只新增，不覆盖**

输出摘要：
  files=<N> bytes=<N> sha256-manifest=<路径>
```

**完整产物表**（四个文件的字段含义）见 `templates/_快照README模板.md` §一 —— 那是对外可读的版本，本节是契约。

### 三条纪律

1. **只新增，不覆盖任何已有快照。** 覆盖快照 = 毁掉退路。
2. **快照编号在收尾时回填**进当轮记录（编号晚于快照是正常的）。
3. **它不是 git tag** —— 无 VCS 时没有 tag 可打，manifest 是替代品。

### 三个要件（**缺任何一个，快照在需要时就是不可用的**）

#### 要件 1：还原路径 —— 工具提供 restore，**或者**手工步骤且演练过一次

**只打不还的快照不是退路。** 实测：某项目跑了好几轮才发现快照工具**没有 restore**，
首次真回滚只能手工解 zip + 逐文件 SHA 断言（四段式），且这个事实
**开放登记了 3 轮无人处理** —— 因为「打快照」这个动作本身不提醒还原不可用。

二选一，**必须在本项目的 `快照/README.md` 里显式写明选了哪个**：

| 选择 | 要求 |
|---|---|
| **工具提供 restore** | 命令写进 README；**验收判据 = 真正跑一次还原并留证** |
| **手工还原步骤** | README 写清可执行步骤（解压 → 覆盖 → 逐文件 SHA 核对 → 回读）；**必须演练过一次并留证** |

> **判据是「演练过」，不是「写下来」。** 没跑过的还原步骤与没有步骤等价 ——
> 第一次真需要它时，你会在最慌的时刻第一次读它。
> 演练证据：还原后的 SHA 清单与 manifest 逐行一致（留输出摘录）。

#### 要件 2：覆盖口径自检 —— 声明覆盖 ≠ 实际覆盖

覆盖集是**目录白名单**时，根级散文件（`.gitignore` / `.editorconfig`）
**静默地**落在所有 manifest 之外。实测：某项目的 `Project/.gitignore`
从未进过任何一份 manifest，靠收尾断言撞上才发现。

**契约**：每次打快照时，追加一条**差分断言**：

```text
覆盖自检：
  声明集合 = 扫描规则命中的文件（递归）
  磁盘集合 = 可写域下的实际文件（递归，排除明确排除项）
  差分：
    - missing_from_manifest = 磁盘有、声明没有  → 必须为 0，或逐条在 meta 里点名为「有意排除」
    - stale_in_manifest    = 声明有、磁盘没有  → 必须为 0（说明扫描规则过时）
  两向差分都必须打印计数，不能只打印一侧
```

**为什么两向**：只查「少了什么」会漏掉「扫描规则指向一个已经不存在的目录」——
那时 manifest 看起来完整，实际什么都没覆盖。

#### 要件 3：快照索引文件自身的覆盖

`快照/README.md`、manifest 索引这类文件是**工具自己的元数据**。
它们常常被工具**自排除**在扫描面外 —— 于是「用来保护一切的目录，
它自己的说明文件没有退路」，而且**静默**。

二选一，**必须显式**：

| 选择 | 要求 |
|---|---|
| **纳入覆盖** | 索引文件本身也在 manifest 里（推荐） |
| **不纳入** | 在 README **显著位置**声明「**本文件无快照退路**」，并给出替代留痕义务（例如它每次改动必须在操作记录里留 OP） |

> **判据**：打开快照目录，任选一个文件问「它坏了怎么回去」——
> 答不出，就是这一条没做到。

### 用 manifest 算「工作区是否干净」

无 VCS 时没有 `git status`。用 `snapshot -Baseline <上一份 manifest>` 得到
added/removed/changed 三组清单，**这就是脏度度量**。

**产物落点**：`<GOV_ROOT>/快照/`（**无 VCS 时唯一退路**；有 git 时此目录可不要）。
**`.diff` / `.patch` / `.orig` / `.rej` / `.bak` 一律落缓存目录**，不进治理目录。

## 四、走查证据包装（有人工验收时）

### 契约

```text
输入：走查脚本路径 + Label

行为：
  1. 跑脚本
  2. 在证据目录写 walk-audit-<时间戳>-<label>.json：
       { verdict: "PENDING_HUMAN_REVIEW",
         items: [ { name, status: PASS|FAIL|UNDECIDABLE, detail } ],
         counts: { pass, fail, undecidable } }
  3. 日志落缓存目录
  4. 无显示环境 / 脚本无法启动 → 全部条目记 UNDECIDABLE，
     **不得写空 items 后当 PASS**（0 条证据 ≠ 全部通过）
```

### 三条纪律

1. **`verdict` 初始必须是 `PENDING_HUMAN_REVIEW`，且不得由执行轮自己改成 PASS。**
   执行者既生产证据、又裁决证据 = 没有裁决。（`anti-patterns.md` #1）
2. **记录里的条数必须与日志逐条核对一致。**
   实测踩过两次：记「21/21」实测 **20**、记「13/13」实测 **14**。
   根因都是**只数了关键字面，漏掉「CDP 附着」之类的前置断言**。
   **计数从日志机械抽取，不手写。**
3. **任何走查脚本（含临时自制的）都必须产这个包装文件** ——
   「自制脚本直跑」不是豁免理由。

## 五、给生成件的建议

生成时在门禁表里这样写：

| 门 | 命令 | 状态 |
|---|---|---|
| 文档基线同步 | `node <脚本路径>` | <已有 / **待实现（契约见本文档）**> |
| 引用完整性 | `<命令>` | <已有 / **待实现**> |
| 快照 | `<命令>` | <已有 / **待实现**；本项目<有/无> VCS> |

**「待实现」是诚实的写法。** 不要写一个不存在的命令 ——
那会让门禁名存实亡，而且**没人会发现**（因为没人在跑它）。

## 六、自愈出口契约（每个阻断门都要回答）

> **本节是契约，不打包任何脚本。** 它只要求目标项目在门禁表里写清「红了谁修」；
> 修复器本身由目标项目自己实现，**不在本 skill 里发布**（见文首「本 skill 不打包脚本」）。

### 为什么需要它

一道**恒红的阻断门**等于治理体系的空转开关：整轮「应用失败 → 回滚」之后，
没人知道下一步该改哪里。而「再跑一次」不是修复 —— 它只是把同一个红再走一遍。

### 三条契约

1. **同源**：检测谓词与修复谓词必须来自**同一份**常量 / 正则 / 基线表。
   各写一份 → 要么「检出但不修」恒红，要么修复方向与检测相反。
2. **保守**：修复器只改**归属唯一**的条目。
   命中 0 处或 ≥2 处 → **只报告，不改写**（猜归属会改错正确的内容）。
3. **可演练**：必须支持 `--dry-run`（只报告将改什么），
   且**被跳过 / 被抑制的条数必须打印** —— 否则抑制标记会变成藏污纳垢处。

### 顺序

**机修先于校验**（`修 → 验`）。反过来做，永远差一步。

### 机修与手工都没有时

**降为报告级，不挂阻断。** 注意顺序：**先看手工出口** —— 类型检查、单测、构建这类门
 通常没有机修命令，但有明确的手工修复步骤，**它们仍然是阻断门**。
 只有「机修写不出、手工也写不出可执行步骤」的检查项才降级 ——
 把修不了的东西挂在阻断位上，等于让整条链路永久红灯。
 门禁表里写 `报告级`（见 `core/gates-and-holds.md` §一）。

### 验收

随便挑一个阻断门，回答：「它红了，下一个动作是什么？」
答得出来、且不是「再跑一次」→ 这一行填完了。答不出来 → 它应该降为报告级。

## 七、容器状态机一致性（`status-check` 型） 【必选 · 标准档起】

> **为什么单列一份契约**：框架对**文件名**有门（引用完整性）、对**计数**有门（基线同步）、
> 对**快照**有门，但**对「这个容器里允许出现哪些状态值」没有任何门**。
> 于是状态字段成了**纯文本纪律** —— 而纯文本纪律在密度上来后**必然漂移**。

### 解决什么

每个容器都有一个**隐含的状态机**：`活跃计划/` 里只能是「未完成」的东西，
`归档计划/` 里只能是「已完成」的东西。规则写在容器 README 里，
但**没有任何退出码**。实测：某项目 14 份归档计划件里 **4 份**状态停在
「已派发 · 未开工」/「执行中」，跨三个执行轮无人发现 —— 而同一棵治理树里，
问题容器与偏差容器**都自建了**状态断言（所以那两个容器没漂）。
**覆盖不均 = 没被覆盖的那个容器必漂。**

### 契约：**双向**断言，按容器各自的值域

| 容器 | 字段 | 合法值（**终态集**） | 断言 |
|---|---|---|---|
| `活跃计划/` | 计划件 `- 状态：` | 非终态：`已派发 · 未开工` / `执行中` / `已闭环 · 待归档` | **必须 ∉ 仅含 `已归档` 的终态集** —— 出现 `已归档` 即应移动 |
| `归档计划/` | 同上 | **`已归档`（唯一）** | **必须 ∈ 终态集** |
| `问题记录/` | `- 状态：` | `开放` | 必须 = 开放 |
| `问题归档/` | 同上 | **`已关闭`（唯一）** | 必须 = 已关闭 |
| `执行偏差/` | `- 状态：` | 非终态 | 必须 ≠ `已闭环` |
| `偏差归档/` | 同上 | **`已闭环`（唯一）** | 必须 = 已闭环 |
| `丢弃计划/` | 计划件 `- 状态：` | `已作废` | 必须 = 已作废 |
| `休眠计划/` | 计划件 `- 状态：` | `休眠` | 必须 = 休眠（blockquote 形态也认） |

**双向的含义**：两个方向都要断言，缺一个就漏一半：

- **归档容器内 ∈ 终态** → 抓「没做完就归档」与「归档时忘了回填」；
- **活跃容器内 ∉ 终态** → 抓「做完了没归档」—— 这条更值钱，
  因为它提示的是**该做的动作还没做**，而不是已经发生的错误。

### 三个实现要点

1. **按内容匹配，不按固定行号/固定前缀**。状态字段可能写成 `- 状态：X`、
   `> **状态：X**`、表格行 —— 只认「`状态` 后跟冒号与值」这个形态。
2. **值域来自上表，不是从文件里学**。从文件里学 = 「4 份都写成未开工」
   会被当成合法值域，断言恒真。
3. **归档件没有实态可对照**。这道门只验**字面属于终态**，
   **不验**「字面与实态是否相符」（那要靠完成宣告的动作清单，不是门）。

### 与「断言设计禁忌」的关系

§一 的三条禁忌**同样适用**：业务状态是**语义**，**不得**用「目录里有几个文件」代替；
状态值域是**有限枚举**，可以查**成员资格**，不要查「顺序/连续性」（那没有意义）。

### 生成时怎么写

门禁表里写 `状态机一致性 | <命令> | 待实现（契约见本文档 §七）` ——
**不要**写一个不存在的命令。本项目没有这门时，至少要把它列进 `工具/README.md`
的重建清单，否则它就是「有规则、无执行」。

## 牙齿验证（所有契约共用）

**每一道门接线当轮都要做一次牙齿验证**：临时制造一条它本该抓到的违规 →
断言它**变红**，且**精确报出位置**（文件 + 行号/条目）→ 还原。

> **没见过它变红的门，等于没有门。**
> 你只知道它不报错，不知道它会报错 —— 而后者才是门存在的意义。

### 三态验证（有修复器时）

只做「造违规 → 变红」是**单侧**验证，会漏掉「**范围过宽 = 假绿**」：
判据切片没剥离注释行，而注释里恰好含被检查的字符串 → 注入缺陷**竟未检出**。

| 态 | 制造什么 | 期望 |
|---|---|---|
| ① **注入** | 一条真违规 | 变红，且**精确报出位置** |
| ② **换写法** | 同一违规换个措辞 / 标点 / 位置 | **仍然变红**（防止判据只认一种字面） |
| ③ **修复态** | 已修好的输入 | **零漂移**：退出码 0，且**不误报** |

> **没有修复器时**，第 ③ 态记「不适用 + 原因」，**不得省略**（静默跳过 = 漏做）。
> 「修好了」必须由**独立**于修复器的手段确认 —— 用修复器自己验证自己，等于没验。

**逐门验证清单**（做法相同，违规不同）：

| 门 | ① 注入什么 | ② 换个什么写法 | ③ 修复态检查 |
|---|---|---|---|
| 文档基线同步 | 加一个源文件但不动基线常量 | 换个目录放同样的文件 / 改文件名大小写 | 基线回填后 `measured` 全相符 |
| 引用完整性 | 写一个指向不存在路径的引用 | 用行内代码包住死链 / 换相对路径写法 | 删掉死链后 `dead=0` |
| 快照 | 对已有快照再打一次同名快照 | 换 label 大小写再打一次 | 只新增不覆盖 |
| 走查证据包装 | 让 `verdict` 由执行轮自己改成 PASS | 改成别的等价绿值 | 初始仍为 `PENDING_HUMAN_REVIEW` |
| 自愈出口（§六） | 让修复器改一个归属不唯一的条目 | 让它命中 0 处 | 修复后检测门变绿，且非目标项未变 |

**记录方式**：把每次验证的「制造了什么 / 报了什么 / 是否精确 / 修复态是否零漂移」
写进当轮记录。**没留痕的牙齿验证等于没做**（本框架的普遍规律）。
