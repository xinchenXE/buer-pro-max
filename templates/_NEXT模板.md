# 微型档：`NEXT.md` 模板 【可选 · 触发：尽调判出微型档】

> **微型档的正确处置是不装治理体系。**
> 给一份约 15 行的 `NEXT.md`，这就够了 —— 加上 `git commit -m "<做了什么>"` 本身就是闭环。
>
> **为什么这个规模装治理只有坏处**：你会花时间填一份没有人读的模板，
> 而那份模板的存在会让你**误以为自己有治理** —— 这比没有更糟。

---

## 什么时候用微型档

- 单文件脚本、CLI 小工具、周末实验、一次性的数据处理
- 1–2 个源文件；没有测试或只有一次冒烟验证
- **你不打算回来维护它**

**判据**：如果你**不确定**下次什么时候会打开这个文件夹 → 微型档。

---

## 模板（复制为 `<项目根>/NEXT.md`）

```markdown
# NEXT

## 下一步
- [ ] <下一件要做的事> — 做到什么样算完：<...>

## 已决定
- <日期> <决定了什么> — 为什么：<...>

> **尽调结论落这里**（微型档不生成治理根，也没有 `项目清单/`）：
> 用 2–3 行写清「探到了什么 / 判了什么档 / 为什么」即可，不要套七节模板。

## 坑
- <踩过的、下次别再踩的>
- <例：这个 API 在空列表时返回 NaN，要先判空>
```

---

## 三条纪律

1. **「下一步」只留一条。** 多于一条说明它已经不是微型项目了 → 升档。
2. **「已决定」记的是「为什么」**，不是「做了什么」—— 做了什么 `git log` 里有。
   为什么没有。
3. **「坑」是这份文件真正的价值。** 前两节可以猜，这一节只能踩出来。

---

## 升档信号（出现任一条就该升到轻量）

- 出现**第二件**「还没做完但先放着」的事 → 需要活跃/归档的区分
- 你**开始记不住**上一次改到哪 → 需要逐轮记录
- 你**开始复制粘贴同一个 TODO 列表** → 需要唯一的真源
- 这份 `NEXT.md` **超过 30 行** → 该升档了

升档时：`NEXT.md` 的「下一步」→ 变成 `活跃计划/` 里的第一份计划；
「已决定」→ 变成 `工作范式.md` 的拍板落档或直接进 git log；「坑」→ 变成 `工作范式.md` 的教训节。
**内容不丢，只是换了容器。**
