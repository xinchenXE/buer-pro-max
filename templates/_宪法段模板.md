# 宪法段模板 → 追加进 `AGENTS.md` 【必选】

> **这是整套交付物里唯一会被每个会话自动加载的部分。**
> 完整规则在 `<GOV_ROOT>/`，但**没人会自动读它** —— 只有这里的内容是「不用找就能看到」的。
>
> **合并方式**：在 `AGENTS.md` **末尾追加**一节，**绝不覆盖**既有内容。
> 追加处写明日期与来源理由。若目标项目已有 `AGENTS.md`，
> 先记录追加前的行数（事后能回答「这节是什么时候进来的」）。
>
> **五档长度**：微型 **不写** / 轻量 ≈40 行 / 标准 ≈100 行 / 完整 ≈200 行 /
> 重型 ≈200 行 **+ 单独的角色与权限矩阵**。
> 按尽调结论选，**宁可先短一档** —— 宪法每多一条，每条的实际约束力就低一分。
>
> **微型档不要生成这一节** —— 那个规模该给的是 `NEXT.md`（见 `templates/_NEXT模板.md`）。

---

## 一、完整档模板（照抄后按 `<...>` 填）

```markdown
## 项目治理（<日期> 立，**对本仓库每次会话绑定**）

本仓库的完整规则见 `<GOV_ROOT>/工作范式.md`；本节是**绑定摘要**，**冲突以 `工作范式.md` 为准**。
**默认阅读顺序**：本节 → `<GOV_ROOT>/README.md` → `<GOV_ROOT>/活跃计划/README.md` → 按需下钻。

### 铁律（不可违背）

1. **零上游改动**：`<上游路径>` 只读，任何分支不得编辑其内文件；上游版本的更新与
   产品行为改动**必须分开提交**。判据：`<上游目录>` 的文件指纹与其 pin 记录一致。
2. **只经公开面集成**：只允许通过**已文档化**的公开面（契约、事件、扩展点、样式变量、路由）
   与上游交互。禁止读取上游内部存储格式、依赖未文档化的字段。
   判据：本次改动引用的每一个上游符号，都能在 `<接口文档路径>` 里找到条目。
   **找不到 = 硬停**，先补文档或改道，不得「先用着」。
   ⚠ **文档用来判「能不能集成」，不用来判断「有没有」** —— 后者去读上游的契约源码。
3. **门禁全绿才算完成**：见下「门禁」。**不得为了让门禁变绿而放宽门禁。**
4. **headless 安全**：构建、类型检查、单元测试、smoke 测试不得依赖图形界面启动。
5. **未落地的东西不得声明为已落地**：`<隔离工作区>` 在运行时落地前保持文档脚手架，
   不得声明为可加载入口。
6. **凡可能有问题的地方一律和用户讲清楚**（**有用户可见面时**）：风险、边界与限额的**具体数值**、
   推荐做法、以及不这么做的后果，必须出现在**用户实际会看到的那个面**里
   （有 UI → 界面文案；无 UI → CLI 输出 / 异常消息 / 日志 / README）。
   **只写进计划文档不算告知。**

### 授权：登记 / 派发 / 执行（三段互不推定）

- **没有派发件，「执行」这条指令不授权任何代码改动。**
- 派发 = 把队列项**移动**（非复制）到 `活跃计划/` 并改名 `<日期>-NNN-<slug>.md`。
- **「特别授权」＝用户当轮原话点名**文件/目录/改动。
  **泛泛的「继续」「go ahead」不构成授权，不延伸到只读域。**
- 同轮直授是合法旁路，但必须：① 逐字记录原话 ② 写明「未走派发」③ 登记一条偏差。
  **不得事后补造派发文件。**
- 原话必须**逐字**记进记录的「拍板落档」节 —— 概括会丢掉限定条件。

### 可写范围（<日期> 用户规则）

**默认可写 N 处**（处数由尽调定，不要照抄本示例的三条）：`<目录1>` / `<生成物目录，仅工具链写>` / `<本机工具目录>`
**只读（除非当轮特别授权）**：`<逐个列出>`
**文档不是代码**：`<GOV_ROOT>/**` 照常可写。
**档位**：A 自由 / B 谨慎 / C 先论证 / D 受限资产 / E 文档 / F 隔离 / X 永不。
**拿不准按更严一档处理，并登记偏差。**

### 门禁（每轮全绿；判定一律以**退出码**为准）

| # | 门禁 | 命令 |
|---|---|---|
| 1 | <…> | `<真实命令>` |
| … | | |
| — | <不适用项> | **不适用 + 原因**：<原因> |

**不适用的门写「不适用 + 原因」，不留空** —— 空行与「查过没有」在事后无法区分。

### 完成宣告

<五步 / 七步>，缺一不可：<逐条列出>。
**代码地图同步不做 = 完成宣告不成立，该轮计划不得归档。**
**本轮无结构变化时也必须显式声明一行** —— 静默跳过与漏做同罪。

### 硬停（需用户当轮原话）

- <逐条列出具体触发条件，不写「重大改动」>

### 共性教训（六条，别重踩）

1. **证据不自证** —— 走查结论留 ⏳ 等用户确认，执行者不得自己打 ✅。
2. **可见 ≠ 可点** —— 落点核验必须做命中测试（`elementFromPoint` 落在目标或其子树内）。
3. **文档是索引不是世界** —— 判「能不能用」查文档，判「有没有」读源码。
4. **行号会漂** —— 引用 `file:line` 前实测，偏了几处改几处。
5. **静默跳过 = 漏做** —— 无变化也要写声明行。
6. **替换前断言唯一命中** —— `assert old.count == 1`，让「什么都没改」变成显式失败。
```

## 二、标准档删减

删掉：铁律 1·2（无上游时）、铁律 5（无隔离工作区时）、门禁 1·2（无对应命令时）、
「共性教训（六条，别重踩）」保留全部 6 条。**它们与项目规模无关** ——
即便本项目暂时没有 UI / 没有冻结面 / 没有编号序列，**照抄这 6 条也不会错**：
它们是**一句话摘要**，触发条件留在各自的规则正文里（见 `anti-patterns.md`）。
**若确要删某条，在原处写一行「本条不适用 —— 原因：<…>」，不要静默删。**

**哪条要删，就在原处写一行**：`铁律 1·2 不适用 —— 本仓库无外部上游（尽调 <日期>）`。
**不要静默删掉** —— 下一个人不知道这是「不需要」还是「忘了写」。

## 三、轻量档删减

只保留四块：**授权三段** / **可写范围** / **门禁** / **共性教训**。

**铁律只保留 ③「门禁全绿」一条**（见 `iron-rules.md` 顶部的「档位 → 铁律 ID」表）；
另外两条常被一起写的「先计划后实施」「证据不自证」是**核心约束**，不是铁律 ——
它们已经落在上面的「授权三段」与「共性教训」里，不必重复。

## 三·补、重型档增补

在完整档基础上**再加一节** —— 它解决的不是「跨会话失忆」，而是
「**多角色之间谁有权做什么**」。**不要只把完整档放大。**

```markdown
### 角色与权限（重型档必填）

| 动作 | 谁可以做 | 需要谁同意 | 记录在哪 |
|---|---|---|---|
| 登记队列项 | 任何维护者 | — | 队列总表 |
| **派发**（授权开工） | | — | 派发件 |
| **拍板**（口径未定时的裁决） | | — | 拍板落档（逐字原话） |
| **豁免门禁** | | **双签** | 审计台账 + 理由 |
| **推翻已冻结的记录** | **任何人都不得**（唯一例外：事实性更正 + 注记） | | |
| 发布 | | 复核 | 发布台账 |

**「特别授权」在重型档里指：<角色> 在当轮明确点名文件/目录/改动。**

### 发布纪律（有发布流程时必填）

- 版本号 **双线制**：dev 线与 release 线**独立**，一条线的构建**不消耗**另一条的号
- **未明说大版本时只加末尾数字**；不得自行升级
- 发布前置检查：<版本号格式断言>，不通过则**构建失败而非告警**
- **实现完成 ≠ 发布完成**：前者进逐轮记录，后者进**发布台账**
```

**重型档的三个独有机制**（缺一即退化为「完整档的放大版」）：

1. **角色与权限矩阵** —— 单人项目里四件事是同一个人，所以能合并；重型必须拆开写，
   否则「谁批准了这次改动」无法追溯。
2. **不可变台账** —— append-only、带指纹、关键动作双签。
   **连项目所有者也不能改写冻结面**，否则审计失效。
3. **发布纪律** —— 很多组织只在「实现完成」层做治理，然后在「发布完成」层出事。

**编号空间爆炸的对策**：四套全局序列横跨多仓库、多团队时，
用 **命名空间前缀**（`WEB-001` / `API-013`），每个命名空间**独立计数**，总表里**分区列出**。

**宪法过长的对策**：不要去重写它，**去拆它** ——
必读 20 行（铁律 + 授权 + 硬停）+ 分区细则（按需查）。

## 四、写法纪律

1. **每一节都要能被"核对"**，不能只是态度。
   ✅ 「判据：本次改动引用的每一个上游符号都能在《接口文档》里找到条目」
   ❌ 「应尽量使用公开接口」
2. **可执行的东西给命令**，抽象的东西给判据。
3. **长度就是约束力**。宪法超过一屏，人就只读第一屏；
   **把所有条目当同等重要，等于没有重点**。
4. **追加，不改写**。`AGENTS.md` 的既有内容不动 —— 它是别人的历史。
5. **在文件里注明本节与 `<GOV_ROOT>/工作范式.md` 的关系**（摘要 vs. 完整），
   免得两处内容被分别独立修改后互相矛盾。

## 五、常见错误

| 错 | 后果 | 对 |
|---|---|---|
| 把完整范式整份复制进 `AGENTS.md` | 宪法膨胀到没人读，且与源文件双维护 | 只放**绑定摘要**，指向完整版 |
| 覆盖既有 `AGENTS.md` | 抹掉别人写的历史与规则 | 末尾追加一节 |
| 把探不到的项留空 | 事后无法区分「查过没有」与「没查」 | 写「不适用 + 原因」 |
| 写「重大改动需要确认」 | 执行者每次都要猜「什么算重大」 | 写具体触发条件 |
| 省略「泛泛的继续不构成授权」 | 默认范围会在一周内膨胀掉 | 写死这句 |
| 把共性教训删掉换成口号 | 下一个会话会一模一样地重踩 | 保留 6 条一句话版本 |
