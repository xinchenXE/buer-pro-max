# 工作范式模板 → `<GOV_ROOT>/工作范式.md` 【必选】

> **这是整套体系里最重要的生成物。** 它是**规则的权威载体** ——
> 铁律、容器分类规则、实施纪律、门禁、完成宣告全在这里，其他文档都指向它。
>
> 生成树里点了这个文件，但**光有宪法段不够**：宪法是摘要（给每个会话自动加载的），
> 这份是**全文**（要查细则时读的）。两者的关系必须在两边都写明。
>
> **长度**：轻量 ≈60 行 / 标准 ≈250 行 / 完整 ≈500 行 / 重型 同完整。
> 下面 `## 三` 之后的「实施纪律」各节**必须按目标项目重写** —— 不要照抄 `§3.x` 的示例标题。

> **下面各节是本项目自己的实施纪律。** 原体系有「代码组织 / 设置与数据面 / 样式纪律 /

> **不要留空节** —— 用不上的就删掉，并说明为什么不适用。

### 3.1 <分层/模块组织>
<例：纯逻辑与视图分离、跨组件状态怎么传、依赖方向、禁止的跨层引用。都要给判据。>

### 3.2 <数据与状态面>
<例：谁能写、谁能读、只读镜像优先于复制写面、序列化约束。>

<例：哪个语言是 key 集真理源、另一语言逐键对齐、上游字符串不可改只能视觉接管。>

<例：三返回路径（✕ / 遮罩点击 / Esc）、Esc 只退最上一层、关闭清瞬态。**给出单测落点。**>

## 写法纪律

1. **「变更记录」必须在头部**，**只增补不静默改写** —— 这条纪律本身要写在文件里，
   否则第三次改动时就会有人直接改正文。
2. **每条规则给判据，不给态度。**
   ✅ 「判据：本次改动引用的每一个外部符号都能在《接口文档》里找到条目」
   ❌ 「应尽量使用公开接口」
3. **`§三 实施纪律` 各节标题按项目重写**，不要保留原体系的标题当占位 ——
   一个空节比没有这一节更糟。
4. **用不上的节直接删，并在删除处不留痕迹**（不要写「本节不适用」七次）。
   只有**铁律**与**门禁**的「不适用」需要留字（因为它们是全集的一部分）。
5. **本文件与宪法段的关系必须在两边都写明**，否则两处会被分别独立修改后互相矛盾。

## 与宪法段的分工

| | `AGENTS.md` 宪法段 | `工作范式.md` |
|---|---|---|
| 长度 | ~40 / ~100 / ~200 行 | ~60 / ~250 / ~500 行 |
| 谁读 | **每个会话自动加载** | **按需查阅** |
| 写什么 | 铁律、授权口径、可写范围、门禁表、硬停、**6 条教训一句话版** | 上面全部 **+** 容器分类细则、实施纪律全文、完成宣告全步骤、环境事实 |
| 冲突时 | 判决 | 判决（**本文件是权威**，宪法是摘要）|

> **这一条必须与 `_宪法段模板.md` 的「冲突以 `工作范式.md` 为准」保持一致。**
> 两处方向相反时，**以本文件为准** —— 但那就意味着宪法段写错了，
> 应当**同轮改宪法段**，而不是让矛盾留着（`doc-sync-discipline.md` §一）。

**维护义务**：改任一处必须在**同一轮**改另一处。这是 `doc-sync-discipline.md` §一
说的「规则载体多处同步」在本体系内部的第一个实例 —— **它就是最容易腐化的那个。**
