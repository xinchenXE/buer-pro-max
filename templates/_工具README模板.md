# `工具/` README 模板（可选容器） 【可选 · 触发：要自制门禁脚本】

> **它回答：门禁脚本住在哪、怎么写、怎么不让它腐化。**
>
> **本 skill 不打包脚本**（见 `README.md` §五 取舍 1），只给**契约**（`references/tool-contracts.md`）。
> 本容器是这些契约在目标项目里的**落脚点**。
>
> **未生成本容器时**：门禁命令仍写在门禁表里，只是脚本散落在项目原有的位置
> （`scripts/`、`tools/`、`Makefile` 目标）—— 那不是错，只是少了一个登记处。

---

## 模板

```markdown
# 工具 · 治理门禁脚本

> 本目录存放**治理体系自己的门禁脚本**（不是产品代码）。
> 每支工具的**契约写在本目录各自的头注释里**（本文件不复制契约正文），
> 本文件是**索引与纪律**。

## 一、本目录有什么

| 脚本 | 作用 | 契约 | 日志落点 |
|---|---|---|---|
| `<脚本名>` | <一句话> | <契约位置> | `<缓存目录>/门禁与走查日志/` |

## 二、三条纪律

### 1. 路径常量走 sidecar，不写在脚本里

脚本本体**保持纯 ASCII**；一切非 ASCII 的路径常量放一个单独的配置文件
（如 `scan-paths.txt`），脚本读取它。

**为什么**：Windows PowerShell 5.1 按 ANSI（中文机器上是 CP936）读取无 BOM 的 `.ps1`，
**UTF-8 中文路径会被解码坏掉**。同理，`.cmd`/`.bat` 里紧跟非 ASCII 注释的命令行会被**吞掉**。
把路径挪出去，是最省事的根治法。

```text
# scan-paths.txt（UTF-8）
# 脚本用 [IO.File]::ReadAllLines 读它，解码正确。
repoRoot=<绝对路径>
governanceRoot=<治理根>
cacheLogDir=<治理根>/缓存/门禁与走查日志
# 可选容器
# exclude=<治理根>/<自增长容器>/
# liveScope=<治理根>/<活文档目录>
```

### 2. 基线数字只有一处

**文档基线同步**类脚本的基线常量，写在脚本里的一个对象或一个 sidecar 文件；
**规则文档引用它，不另写一份**。两处各写一份 → 必然分叉。

### 3. 判定一律以退出码为准

不要把输出的自然语言当判据。
（PowerShell 下管道的退出码不可信 —— 一律 `*>` 重定向到日志文件，再判 `$LASTEXITCODE`。）

## 三、加一支新工具时

1. **先落实契约**（扫什么、判据、输出、牙齿验证）—— 写进该脚本的头注释。
2. **验证它有牙齿**：临时制造一个违规 → 确认它变红且**精确报出位置**。
   没验过牙齿的门禁，你只知道它不报错，不知道它会报错。
3. 在 §一 表里加一行。
4. 接进门禁链，并在门禁表里登记。

## 四、不在这里放什么

- ❌ **产品代码** —— 那是被检查的对象，不是检查者
- ❌ **一次性脚本** → 落 `<缓存目录>/一次性脚本/`（它们用完即弃，不该进版本控制）
- ❌ **生成物** → 落 `<缓存目录>/`

## 五、权威

契约与判据：**各脚本自己的头注释**。
本目录只登记**有哪些工具、住在哪**，不复制契约正文。
```

## 什么时候生成本容器

| 情况 | 建议 |
|---|---|
| 项目已有门禁脚本（`scripts/`、`Makefile`、CI 配置） | **可以不生成** —— 在门禁表里指向原位置即可 |
| 需要自制门禁（文档基线同步 / 引用完整性 / 快照） | **生成** —— 让自制工具有一个明确的住处，而不是散在根目录 |
| 多人协作、门禁会被别人接 | **生成** —— 契约集中一处，交接成本最低 |

> **本容器的价值不在"存脚本"，在于"契约集中在能被找到的地方"。**
> 脚本散在根目录时，加一支新工具的人不会去看旧工具的契约，于是每支工具都长一套自己的口径。
