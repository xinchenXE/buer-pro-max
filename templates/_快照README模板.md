# `快照/` README 模板（条件容器） 【可选 · 触发：无 VCS 或治理根不在仓库内】

> **它回答：改坏了怎么回去。**
>
> **只在「无 VCS」或「有 VCS 但治理根不在仓库内」时才需要** ——
> 有 git 且治理根在仓库内时，回滚手段就是 git，本容器可整个不要。
> 另外两种情形下它是**唯一退路**，必须写进宪法的硬停清单（判据见本文件末的触发表）。
>
> 契约见 `references/tool-contracts.md` §三。

---

## 模板

```markdown
# 快照 · 无 VCS 时的唯一退路

> **本项目没有版本控制**，故本目录是「改坏了怎么回去」的**唯一答案**。
> 它在宪法里是**硬停项**：覆盖本目录的任何文件都是禁止操作。

## 一、怎么打

```sh
<快照命令> -Label <slug> -Zip
```

产出（编号形如 `snap-YYYY-MM-DD-<slug>`）：

| 文件 | 内容 |
|---|---|
| `snap-<日期>-<label>.manifest.tsv` | `SHA-256 <TAB> 字节数 <TAB> 相对路径` |
| `snap-<日期>-<label>.meta.json` | 时间、范围、文件数、字节数、排除项 |
| `snap-<日期>-<label>.diff.tsv` | 带 `-Baseline` 时：added / removed / changed |
| `snap-<日期>-<label>.zip` | 带 `-Zip` 时：源码压缩包 |

## 二、三条纪律

### 1. **只新增，不覆盖任何已有快照**

覆盖快照 = **毁掉退路**。这是本目录唯一真正危险的操作。

### 2. 全量替换类改动**动手前**必须打

判断口径：**这次改动如果错了，能不能一个个文件改回来？**
不能 → 先打快照。

### 3. 快照编号**回填进当轮记录**

编号回填**晚于**快照是正常的（先打、后写记录）。
但**必须回填** —— 否则这份快照在事后无人知道它对应哪一轮。

## 三、用来度量「工作区是否干净」

无 VCS 时没有 `git status`。用带 `Baseline` 的差分**就是**脏度度量：

```sh
<快照命令> -Label check -Baseline <上一份 manifest>
# → diff.tsv 里 added / removed / changed 三组清单
```

这比「肉眼看着像没动过」可靠得多。

## 四、不在这里放什么

- ❌ **可重新生成的产物**（构建输出、日志）—— 它们应当被排除在扫描范围外，
  否则每份快照都不同，差分成噪音
- ❌ **已被忽略的目录**（依赖、缓存）—— 同上
- ❌ **二进制大件**（安装包、素材集）—— 除非它是退路的一部分，
  否则体积会失控

## 五、保留策略

**本目录只增不清理。** 它会一直增长。

> 这是**有意为之**：快照的价值是「任意历史时刻都能回去」，
> 自动清理会让这条保证悄悄失效，而且**失效时不会报错**。
> 真要清理，必须是**显式的用户决策**，并写进操作记录（含删了哪些、指纹是什么）。

## 六、还原路径（**只打不还的快照不是退路**）

> 本文件开头写的是「改坏了怎么回去」—— 如果这里没写怎么回去，它就只是「怎么留档」。

**本项目选择**：<工具提供 restore / 手工四段式>

**手工四段式**（默认写法；若工具提供了 restore，把第 1 步换成那条命令即可）：

1. 解压 `snap-<日期>-<label>.zip` 到临时目录
2. 按 `manifest.tsv` 逐条覆盖回原路径
3. 逐文件核对 SHA-256 与字节数
4. 回读：确认非目标文件未被改动

**工具提供 restore 时的命令**：`<还原命令>`

**验收判据**：以上步骤**演练过一次**并留证（还原后的 SHA 清单与 manifest 逐行一致）。
**没跑过的还原步骤与没有步骤等价** —— 第一次真需要它时，你会在最慌的时刻第一次读它。

**演练日期**：<日期>｜**证据**：<路径>

## 七、覆盖口径自检（每次打快照都要跑）

**声明覆盖 ≠ 实际覆盖。** 覆盖集是目录白名单时，根级散文件会**静默**落在
全部 manifest 之外，而且不会报错。

```text
missing_from_manifest = 磁盘有、manifest 没有 → 必须为 0，或逐条在 meta 里点名为「有意排除」
stale_in_manifest     = manifest 有、磁盘没有 → 必须为 0（说明扫描规则过时）
```

**两向都要打印计数** —— 只查「少了什么」会漏掉「扫描规则指向一个已不存在的目录」，
那时 manifest 看起来完整，实际什么都没覆盖。

## 八、本文件自身的退路

<本文件在覆盖范围内 / 不在覆盖范围内>

- **在覆盖范围内**：本 README 也进 manifest（推荐）。
- **不在覆盖范围内**：**本文件无快照退路**。它的每次改动必须在
  `../操作记录/` 留一条 OP，并在注记区写明改了什么。
```

## 什么时候生成本容器

| 情况 | 建议 |
|---|---|
| **无 VCS** | **必须生成** —— 它是唯一退路，且要进宪法硬停清单 |
| 有 git，但治理根**不在**仓库内 | **必须生成**（同上，治理记录不受 git 保护） |
| 有 git 且治理根在仓库内 | **不生成** —— 回滚用 git，本容器是多余的 |

> **判据**：跑 `git rev-parse --show-toplevel`。**失败才算无 VCS，此时必须生成。**
> （只看 `<项目根>/.git` 是否存在会漏掉「仓库根在上层」这种常见情形。）
>
> **生成之后必须回答的三个问题**（对应 §六–§八，缺任何一个这道退路就不可用）：
> ① 怎么还原？（工具 restore 或手工步骤，且**演练过**）
> ② 怎么知道覆盖全了？（两向差分自检）
> ③ 本文件自己坏了呢？（纳入覆盖，或显式声明无退路 + 替代留痕）
>
> ⚠ **恢复 VCS 之后再评估它的去留** —— 有了 git 之后这份快照成了历史包袱，
> 但**删它必须由用户发话**（它可能仍包含 git 历史里没有的东西）。
