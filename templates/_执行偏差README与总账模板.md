# 执行偏差 README + 总账模板 → `<GOV_ROOT>/执行偏差/` 【必选】

> 本目录是**执行期偏差的单一索引**，**不是第二份记录**。
> 每条偏差的**权威原文仍在它所属的计划文档**里；本目录只做**抽取 + 分类 + 判定**，
> **不复制正文**（`doc-sync-discipline.md` 的「不留双份记录」）。

## 一、`README.md` 模板

```markdown
# 执行偏差 · 总账与判定

> 立档：<日期>。本目录是**执行期偏差的单一索引**，不是第二份记录：
> **计划内偏差**的权威原文在各计划文档的「偏差记录」小节里，本目录只做
> **抽取 + 分类 + 判定**，**不复制正文**；
> **框架期偏差 `DEV-NNN`** 的权威原文就是本目录下**一条一个**的独立文件。
> 逐条清单见 [偏差总账.md](偏差总账.md)。

## 一、计数口径

- **范围**：<规则文档生效日期> 起所有带「偏差记录」小节的计划文档，共 **N 份**。
- **计数单位**：该小节下的**顶层编号条目**（每份从 1 连续编到 N，无跳号、无重号）。合计 **N 条**。
- **不计入**：<范式生效前的、散写在别处的，写明为什么不并入>
- **本节只数第一轨（计划内）**。`DEV-NNN` 的条数以 `偏差总账.md` §二 的行数为准 —— 两轨口径不同，不合并成一个总数。

## 二、双轨（**不混编**）

本目录实际记**两轨**：

| 轨 | 权威原文在哪 | 编号 | 落盘形态 |
|---|---|---|---|
| **计划内偏差** | 散在各计划文档的「偏差记录」节 | 每份独立编号 | 不单独成文件，留在计划文档内 |
| **框架期偏差 `DEV-NNN`** | **逐条独立文件，原文即文件本身** | 全局序列 | **一条一个 `DEV-NNN-<slug>.md`** |

**两轨编号互不占用、互不换算**：不把 `DEV-005` 叫「第 229 条」，
也不把计划内第 5 条叫 `DEV-005`。
队列总表的「开放执行偏差」**只算第二轨**。

**`DEV-NNN` 一条一个文件 —— 这是硬要求，不是风格偏好。** 用 `_偏差模板.md`
复制成 `DEV-NNN-<slug>.md`，**不得把多条偏差写进同一个文件**、也不得写成一张滚动追加的清单。
理由有三条，缺一条这条规则就会在第三轮被省略：

1. **归档单位是文件。** 闭环动作是「**移动**（非复制）入 `偏差归档/`」——
   多条挤在一个文件里时，只有全部闭环才能整份移动；只要有一条还开着，
   整份文件就被钉在原地，**已闭环的那些永远进不了归档**。
2. **状态机是逐条的。** 每条偏差有自己独立的「开放 / 已闭环」状态。合并记录时
   只有文件级状态，于是「3 条里 2 条已闭环」这件事无法表达，总账的状态列必然说谎。
3. **编号是全局序列。** `DEV-NNN` 永不复用、`slug` 唯一。合并记录时编号退化成
   大文件里的一个标题，`偏差总账.md` 的「文件」列只能全部指向同一个文件，
   归档后更没有具体落点可指。

> **唯一的例外是「计划内偏差」** —— 它们本来就不单独成文件（见上表第一轨），
> 留在计划文档的「偏差记录」节里按序号追加。**不要把这条例外套到 `DEV-NNN` 上。**

**闭环去向**：`DEV-NNN` 关闭后（补「闭环」章节 + 改本目录 `偏差总账.md` 的状态列
**与文件路径列**）**移动**（非复制）入 `偏差归档/` —— 与 `问题记录/ → 问题归档/` 同构。
`偏差归档/` **只读**，只收已关闭的；**未闭环的一律留在本目录**。
（判据：本目录 = 开放的，`偏差归档/` = 已关闭的。两者不重叠、不留副本。）
**移动后必须把总账「文件」列的路径改成 `偏差归档/DEV-NNN-<slug>.md` 并跑一次引用完整性门禁** ——
只改状态列、不改路径 = 总账指向一个已经不存在的文件。

## 三、六类定义与判定规则

**一条只进一类，按根因归主类**；跨类的在总账摘要里可见但不重复计数。

| 码 | 类名 | 判定规则 |
|---|---|---|
| A | 计划被证伪或改道 | **计划文本自己**的假设/落点/数值错了、漏了一态、或实施主动改写计划口径 |
| B | 实施期缺陷自纠 | 首版**实现或验证脚本自身**有 bug，被真机、门禁或收口审计抓到并修 |
| C | 外部能力缺口 | 根因在**外部能力面**：无公开面、结构性缺席、未注册、行为与文档/假设不符 |
| D | 验证与环境受限 | 根因在**本机环境/工具/沙箱**：真机不可达、验证未做、环境性门禁、平台限制 |
| E | 决策与取舍 | 根因是**产品或用户的主动取舍**：押后另立、有意边界、保留死键、采纳推荐口径 |
| F | 口径细化与留痕 | 计划只给语义/区间，实施把**数值、命名、签名、结构**钉死；以及收尾记录与「无偏差」声明 |

**两条边界规则（判定分歧最多处）**：

1. **根因在外部 → C 不归 A**。字面看是「计划假设被证伪」，但根因是外部没提供 → 归 C。
2. **只影响验证 → D 不归 C**。同一根因，后果只是取不到证、产品行为未变 → 归 D；
   若导致**功能降级** → 归 C。

> **F 类里有一部分严格说不是偏差**，是留痕与收尾记录
> （例：「无功能性偏差」「与验收口径一致，非模拟」）。

## 六、不在这里放什么

- ❌ **计划内偏差的正文** → 权威原文在**计划文档的「偏差记录」节**；本目录只做抽取 + 分类 + 判定
  （**`DEV-NNN` 的正文例外**：它的权威原文就是本目录下的独立文件，见 §二）
- ❌ **把多条 `DEV-NNN` 写进同一个文件** → 一条一个 `DEV-NNN-<slug>.md`；合并记录的后果见 §二
- ❌ **滚动追加式的大清单（一个 `偏差记录.md` 里挂 N 条）** → 那不是本目录的形态；它无法逐条闭环、也无法逐条归档
- ❌ **跨轮操作的记录** → 那是 `../操作记录/`（完整档）的事，不进偏差序列
- ❌ **已闭环的偏差** → 应**移动**到 `偏差归档/`（留在这里，下个会话会以为还没闭环）；未闭环的不移
- ❌ **问题的记录** → 那是 `../问题记录/`（`ISS-NNN`）的事；问题与偏差是两条不同的序列

**为什么这一节重要**：偏差有**两轨**（计划内 / 框架期），
两轨的权威落点不同。放错轨道 = 记了两份、且两份会漂。

## 七、维护纪律

1. **新轮次闭环时**：主规则文件照旧在当轮计划里写偏差记录；本目录**只在下列情况更新** ——
   新增编号条目、某条开放项被闭环或被否决、出现新的复读条目。
   **不要求每轮重写分布表与趋势**，但**条数变了必须同步**。
2. **判定改动留痕**：把「不做」翻成「做」要在该行留下**日期与依据**，**不得静默改写**。
3. **不做第二份正文**：任何情况下都不把计划文档里的偏差正文抄进本目录。
4. **跨轮操作的偏差不进本账**：那些落 `操作记录/`，**不并入**——
   否则两套口径会互相污染。
5. **新偏差一律另起文件**：一条 `DEV-NNN` = 一个 `DEV-NNN-<slug>.md`，
   并在 `偏差总账.md` §二 **追加一行**。**不得**在既有文件里续写、不得合并同类项 ——
   合并会同时破坏归档单位、逐条状态与全局编号（详见 §二）。
   发现历史上有合并记录 → 按一条一文件**拆分**，拆分本身记一条偏差（类型 F，口径细化与留痕）。
```

## 二、`偏差总账.md` 模板

```markdown
# 偏差总账

> 本表是从各计划文档的「偏差记录」节**机械抽取**的；分类码是**唯一的人工输入**。
> 若怀疑抽取有误，**以计划文档原文为准**。
> **§二 一行 = 一个 `DEV-NNN` 文件**；若两行指向同一个文件，说明偏差被合并记录了 —— 拆开，别改表。

## 一、计划内偏差索引

| # | 出处 | 摘要 | 分类 |
|---|---|---|---|
| 1 | <计划> §七 1 | <加粗标题> | A |

## 二、框架期 `DEV-NNN` 索引

| # | 文件 | 标题 | 分类 | 状态 |
|---|---|---|---|---|
| DEV-001 | `DEV-001-<slug>.md` | | | 开放 / 已闭环 |

> **已闭环的行，「文件」列必须写 `偏差归档/DEV-NNN-<slug>.md`** —— 文件已经移动，
> 路径不跟着改，总账就指向一个不存在的目标。开放的行写相对本目录的裸文件名。
```

**「总账可重生成」**：表体是机械抽取的，所以它可以被脚本重建 ——
这一条要写进维护纪律，否则有人会手动维护它，然后它悄悄漂移。
