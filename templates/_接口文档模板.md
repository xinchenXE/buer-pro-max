# 接口文档模板 → `<GOV_ROOT>/<外部接口文档>.md` 【必选 · 触发：有外部上游 / 只读边界】

> **这是铁律 2 的判据载体** —— 没有它，铁律 2（只经公开面集成）**无法执行**。
>
> 铁律 2 说的是「只允许通过**已文档化**的公开面与上游交互」。
> 那么「已文档化」这件事**必须有一个地方可查** —— 就是这份文件。
> 检查某一处引用合不合规，动作只有一个：**拿到这份文件里搜**。
>
> **它是有上游时才生成的。** 尽调判出「无外部上游」→ **不生成本文件**，
> 并在宪法里写明铁律 1/2 不适用及其理由。

---

## 何时生成

| 尽调结论 | 是否生成 |
|---|---|
| 有 submodule / vendored 上游 / 被整体替换的依赖 | ✅ 生成 |
| 无上游，但有「只读区 + 只经公开面跨过」的边界（生成物、第三方 SDK 封装层） | ✅ 生成（把那条边界的公开面写进来） |
| 完全无边界 | ❌ 不生成，宪法里写明不适用 |

## 模板

```markdown
# <上游名> 接口文档

> **本文件是铁律 2 的判据。** 凡本仓库要跨过边界调用/读取上游，
> 必须先在本文件里**登记一个条目**，否则**不得集成**（硬停）。
>
> 口径：**登记的是「面」，不是「用法」。** 一条记录一个可集成的入口点，
> 写清它的**契约形状**与**稳定承诺**。
> **本文件不抄上游源码** —— 只记「哪里有、叫什么、能用什么」。

## 〇、使用方式

1. 要集成某个上游能力 → **先在本文件搜**。
2. 搜到 → 按条目写的方式集成，不得偏离。
3. **搜不到 → 硬停**：先补本文件（含证据），或改道，**不得「先用着」**。
4. 读上游契约源码**可以**用来判断「有没有」（见下「与源码的分工」）。

### 与源码的分工（**易错，必读**）

| 问题 | 查哪里 |
|---|---|
| **能不能集成**（铁律 2 的判据） | **本文件**。本文件没有 = 不许用 |
| **有没有这个能力** | **上游的契约源码**（`packages/**/src/api/*.ts` 之类） |

> **两个方向都会错**，且**同源** —— 都是**把文档当成了世界本身**：
> ① 本文件里没有 → 断言「上游没这个能力」（错，实测可能有）；
> ② 上游源码里有 → 当成可集成（错，本文件没登记就是不许用）。

## 一、<面族 1：如「槽位 / Slot 契约」>

| 面 | 位置 | 契约形状 | 稳定承诺 | 备注 |
|---|---|---|---|---|
| | `<路径:行号>` | <签名 / 字段 / 事件名> | <公开 / 实验 / 未承诺> | |

## 二、<面族 2：如「设置命名空间」>

（同上表结构。**面族按上游的公开面类型分**：slot / 设置 / 路由 / 事件 / 样式变量 / 依赖注入 …）

## 三、<面族 3：如「路由 / Host API」>

## 四、**明确未登记**（容易被误当成可用）

<**这一节很重要。** 逐条列出「上游确实有、但本仓库**不得使用**」的面，并写明原因。
没有这一节，下一个会话会在上游源码里发现一个能力，然后理所当然地用起来。>

| 面 | 为什么不登记 |
|---|---|
| <如内部存储格式> | 铁律 2 明令：读 `storages/*.json` 一类内部格式**一律禁止** |

## 五、维护纪律

1. **登记即承诺**：一旦登记，本仓库就依赖它；上游变更导致失效 → 记一条偏差。
2. **未登记不得使用**：发现有人用了未登记的面 → 那是偏差，不是「补登就行」。
3. **本文件随上游版本走**：pin 更新轮要复核全部条目是否仍成立。
4. **测得的行号带日期戳** —— `file:line` 会漂（**同轮实测，偏了几处改几处**），
   引用前先实测。
```

## 与铁律 2 的挂钩

在宪法段与 `工作范式.md` 里都要写死这句：

> **判据：本次改动引用的每一个外部符号，都能在本文件里找到条目。
> 找不到 = 硬停，先补文档或改道，不得「先用着」。**

## 与「归档」的关系

本文件**不是**冻结文档 —— 它随上游版本演进（pin 更新轮要复核）。
但**每次复核要留痕**（日期 + 变了什么），不得静默改写条目。
