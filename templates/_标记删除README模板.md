# `标记删除/` README 模板（可选容器） 【可选 · 触发：用户选择启用】

> **它就是一个回收站。** 资源、内容、文档 —— 想删的东西先进来，
> 留着的唯一目的是**反悔时还能捞出来**。
>
> 框架里破坏性删除原本只有两态 —— **硬停禁止** 或 **用户授权后真删**。
> 中间缺一个**可逆**态，而这个缺口会逼出两种坏结果：
> 执行者怕删 → 留垃圾（违反容器纪律）；或自行豁免 → **执行者立法**。
> 本容器补上那个中间态：**破坏性删除 = 移动进来**，移动可逆、不减少文件总数，
> 因此**不需要用户原话**；**真删才需要**。
>
> **关键定位：对正式项目来说它相当于不存在** —— 项目本体与所有门禁
> **默认不引用、不读取**；只有用户发话才临时读取。留不留、留多久、删不删
> **全由用户决定**（留着 / 发话还原 / 发话真删）。
>
> 触发条件**由用户选**，优缺点与建议见本文件末的「什么时候生成本容器」。

## 模板

````markdown
# 标记删除 · 回收站（**项目本体默认不读取**）

> **它只有一个用途：留一个后悔的机会。**
> 资源、内容、文档 —— 任何打算删除的东西都可以先进这里，
> 留着它**只是为了反悔时还能捞出来**。
>
> **对正式项目来说，它相当于不存在。** 项目本体（文档 / 索引 / 计划 / 代码）
> 与所有门禁**默认不引用、不读取**本容器；只有**用户发话**时才临时读取它。
> **留不留、留多久、删不删，全由用户决定** —— 用户可以选择继续留着、
> 发话要求删除（真删）、或发话要求捞回来（还原）。
> **框架不设过期、不自动清理、不主动汇报**：要清点，等用户发话。

**编辑性**：追加式 —— `登记.md` 只增不改；文件只有三种动作：**移入 / 还原 / 真删**。
**建立**：<日期>（<轮次>；启用依据见 `<GOV_ROOT>/README.md` 的「可选容器」一行）。

## 一、这里放什么

- 一切**打算删除**的资源或内容 —— 文档、代码、资产、配置、不能重建的生成物，
  只要在可写圈内、原本要被删掉，就先进这里。以**移动**（非复制）方式进入，按**批次**存放：

```text
标记删除/
└── <YYYY-MM-DD>-R<nn>-<slug>/     ← 一批一个目录（同轮同主题的一起进）
    ├── 登记.md                     ← 本批次的清单与授权依据（必建，见 §二）
    └── <原相对路径结构原样保留>/…   ← 被移入的文件（不重命名、不改内容）
```

- 每份 `登记.md` 必含五项：
  **原路径**（逐文件）/ **删除理由** / **授权依据**（用户原话逐字，或规则/计划条款出处）/
  **轮次与 OP 编号** / **SHA-256 清单**（还原与真删都要靠它核对）。

## 二、怎么进（＝本项目破坏性删除的唯一动作）

| 步骤 | 动作 |
|---|---|
| 1 | 建批次目录 `<日期>-R<nn>-<slug>/`，写 `登记.md` 五项（SHA-256 在移动前算） |
| 2 | **移动**（非复制）目标文件进来，**保留原相对路径结构** |
| 3 | 同轮写一条操作记录 `OP-NNN`（触发项 = **移入**；`OP` 是**已登记的第五套序列**，见 `计划队列/队列总表.md` §一） |
| 4 | **回读**（用另一条命令）：原位置已无 ＋ 本容器已有 ＋ **非目标未改** |
| 5 | **引用核对**：指向被移文件的引用逐条改掉（或就地注记），**不留悬空**；改掉之后**不得再指回本容器**（见 §四） |

- **移动不需要用户原话** —— 它可逆、不减少文件总数。硬停约束的对象是**真删**。
- **但可追溯门槛不减**：单批 **> 10 个文件** 时，必须**先在计划项或操作记录里登记该批次**
  （批次目录、文件数、理由），再执行移动。一次误 glob 搬走半个仓库同样要可查。
- **可再生物不进本容器**（见 §五）—— 它们直接删，只记 OP。

## 三、怎么出：**用户三选一**

| 用户的选择 | 条件 | 动作 |
|---|---|---|
| **留着**（默认） | 用户没发话 | 什么都不做。**不清理、不过期、不汇报** |
| **还原**（捞出来） | 用户发话要恢复，或发现删错了 | **移动**回原路径 → 按 `登记.md` 的 SHA-256 逐文件核对 → 追加「还原记录」（不改原文）→ OP + 回读 → 原引用逐条改回 |
| **真删**（永久删除） | **用户当轮原话点名**（硬停） | 先打覆盖本容器的快照 → 删除 → 追加「真删记录」（用户原话逐字 + 快照编号 + 删后核对）→ OP + 回读 |

**没有第四条路。** 执行者不得自行清理、不得设自动过期、不得「顺手删掉」；
**也不得因为「看起来没用了」而替用户判断该删** —— 值不值得留是用户的事。

## 四、怎么用：**项目本体默认不读取**

> 这是本容器与其它容器最大的不同：**它不是项目的一部分，是项目的回收站。**

| 面 | 默认行为 | 只有用户发话时 |
|---|---|---|
| **文档与索引** | 不引用本容器内的任何文件；`项目清单`、README、计划、索引里**不出现**指向它的链接 | 可以临时读取一次，**结论仍以活文件为准**，不入库、不进索引、不写进计划 |
| **代码与构建** | 不读取本容器的任何内容 | 同左 —— **任何情况下都不作为输入** |
| **门禁扫描** | 不作为扫描源（见 §七） | 同左 |
| **引用完整性** | 移入时旧引用**当轮改掉**；**不拿「文件还在里面」当保留死链的借口** | 还原时逐条改回 |

- **恢复的入口只有一条**：移回原路径。**不要直接从本容器引用、导入、构建。**
- 用户发话要「看看里面有什么」时，**读一次、报一次**，然后回到默认态。
- **用户临时读取之后**：不写进索引、不写进计划、不进 `项目清单`；
  若由此产生了新决定，**只记在当轮计划或操作记录里**，回指本容器的批次目录。

## 五、不在这里放什么

- ❌ **可再生物**：门禁日志 / 一次性脚本 / 构建产物 / `__pycache__` / `diff`·`patch`·`bak` ——
  它们是缓存性质，删了能重建，**不构成破坏性删除**，直接删（仍按操作记录留痕）。
  **反向判据**：删掉之后能不能用**一条命令**重建？能 → 不进本容器；不能 → **必须进**。
- ❌ **只读边界内的任何文件**：来自 `apk/`、上游封装层、锁文件、冻结配置的东西 ——
  **「移动」不是绕过只读边界的口子**。把它们搬进来等于删掉了它们。
- ❌ **快照文件**：`快照/` 只增不覆盖不删，任何快照不进本容器。
- ❌ **冻结面正文**（归档件 / 已闭环 `DEV` / 已关闭 `ISS`）：规则禁止删除它们；
  作废走「改状态 + 留号」，不走删除。
- ❌ **被更新取代但仍有留存价值的文档** → 那是 `归档文档/`（历史证据），不是回收站。
- ❌ **复制进来的副本**：只收**移动**件 —— 留副本 = 两份活文件，违反「不留双份记录」。

## 六、留多久、什么时候清

| 问题 | 答案 |
|---|---|
| 保留多久？ | **用户定。** 框架不设过期时间 |
| 什么时候提醒用户？ | **不主动提醒。** 只有用户发话要清点时才列出来 |
| 谁来清？ | **用户发话。** 真删是硬停；执行者不得自行清空 |

**为什么不定自动过期**：自动清理会让「可恢复」这条保证悄悄失效，而且**失效时不会报错**。
与 `快照/` 的保留策略同理。**也不要把「堆积很多」当成清理理由** —— 那是用户的判断。

## 七、扫描面（**门禁必须排除本容器**）

本容器是**回收站**，不是活文档。生成门禁时必须：

| 门禁 | 怎么处理本容器 |
|---|---|
| 文档基线同步 | **不计入基线** —— 否则每移入一个文件，基线数字就假性变化 |
| 孤儿文件 | **不作为扫描源** —— 不要求它里面的文件被引用；**也不作为合法目标** —— 别处不得引用它 |
| 引用完整性 | 指向被移文件的旧引用**必须当轮改掉**；本容器内的文件**不参与**引用检查 |
| 冻结面检查 | 本容器**不是**归档容器 —— 它可写（追加式），不要把它当冻结面 |
| 破坏性删除检查 | **移入不算删除**；**真删才算**，需用户原话 |

## 八、权威

规则正文（删除纪律）见 `<GOV_ROOT>/工作范式.md` 的「删除纪律」节；
硬停口径见宪法段的硬停清单。**本文件不复制规则正文，只写容器机制。**
````

## 什么时候生成本容器（**由用户选**）

**默认建议：`快照/` 生成时一起生成。** 但**最终由用户定** —— 生成前把下面这组对照摆给用户，
让他选「启用 / 不启用」，**不要生成完再问**。

| 选项 | 优点 | 缺点 | 建议 |
|---|---|---|---|
| **A. 与 `快照/` 同源启用**（`git rev-parse --show-toplevel` 失败，或成功但治理根不在仓库内） | 覆盖**唯一真正危险**的情形：文件删了没有任何版本历史能还原。与已有一条触发条件同源，用户不用多记一个判据。且此时快照是时点全量，粒度太粗 —— 本容器补的正是**逐文件**粒度 | 多一个容器；无 VCS 项目本来就要维护快照，容器数会显得多 | ✅ **默认推荐** |
| **B. 所有项目默认生成** | 有 git 的项目也保护**未跟踪文件**（新建后被误删的文件，git 同样救不回来）；且不必在生成时判断 VCS 状态 | 对已熟练用 git 的用户是噪声；`<GOV_ROOT>` 如果本身在 git 里，绝大多数删除都能 `git checkout` 回来，本容器价值被稀释 | 适合**有大量未跟踪产物**或**多人协作**的项目 |
| **C. 不生成**（由用户明确拒绝） | 最少容器；对熟练用户无额外负担 | 破坏性删除重新退回「硬停 / 真删」两态 —— 执行者**要么事事来问，要么自行豁免**。这正是本容器要解决的问题 | 仅当用户明确说「我不要中间态」时选 |

**推荐的问法**（生成前，一次说全）：

> 「这个项目检测到 **<无 VCS / 治理根不在仓库内 / 有 VCS>**。
> 要不要生成 `标记删除/`？
> **好处**：想删的东西先移进回收站，可逐文件捞回来，不需要每次来问你；
> 它**默认不被项目读取**，所以不会污染文档、索引或门禁。
> **代价**：多一个目录，删文件时要多一步「移入 + 登记」。
> **我的建议**：**<启用 / 不启用>**，因为 <一句话理由>。」

**选了之后要做的三件事**（与其它可选容器相同）：

1. 写进 `<GOV_ROOT>/README.md` 的「容器一览」，并在「档位」一节记一行
   `可选容器：本档位默认带 <…>；本次**已生成 / 未生成** 标记删除/，原因：<…>`。
2. 把「破坏性删除 = 移入本容器」这条**写进宪法段的硬停节与工作范式**（见下面的配套）。
3. 在 `项目清单/README.md` 的文档清册里加一行。

> **不生成 ≠ 这件事不用管**：用户选了 C，也要在尽调结论里写明
> 「破坏性删除无中间态，删除一律走硬停」，让这个选择**显式**而不是默认。
