# 治理根 README 模板 → `<GOV_ROOT>/README.md` 【必选】

> **它是整个体系的入口** —— 新会话读到的**第一份活文档**。
> 它的唯一职责：**告诉人从哪开始读、按什么顺序读**。
> 越短越好。它是**地图**，不是**领土**。

---

## 模板

```markdown
# <项目名> · 治理根

> 本目录是本项目的**治理根**：计划、队列、问题、偏差、记录、证据都在这里。
> 规则正文不在这里 —— 在 `工作范式.md`；绑定摘要不在这里 —— 在仓库根 `AGENTS.md`。

## 一、默认阅读顺序

**新会话按这个顺序读，每站只读到你需要的深度为止：**

| # | 读什么 | 为什么 |
|---|---|---|
| 1 | **`AGENTS.md` 的「项目治理」节** | 绑定约束。**经 `CLAUDE.md` 的 `@AGENTS.md` 导入后自动加载** |
| 2 | **本文件** | 方向：有哪些容器、读什么顺序 |
| 3 | `活跃计划/README.md` | 现在在做什么 + 最近 3 轮 + 代码地图三节 |
| 4 | `计划队列/队列总表.md` | 有多少活、优先级是什么（**计数的唯一真源**） |
| 5 | 最近一份 `登记提示词/` 交接件（**仅当生成了该容器**） | 上一个会话留给你的话：从哪开始、别踩什么坑 |
| 6 | `工作范式.md`（按需） | 要写计划 / 要动代码 / 拿不准规矩时，查全文 |

> **别一上来读全部。** 按需下钻 —— 第 3、5 站通常就够开工了。

| `休眠计划/` | 用户明确暂缓 | **冻结** |

| `执行偏差/` | 偏差索引与六类判定 | 活 |

## 五、不在这里放什么

- ❌ **规则正文** → 在 `工作范式.md`；本文件只是**地图**，不是**领土**
- ❌ **计数** → 在 `计划队列/队列总表.md`
- ❌ **逐轮叙事** → 在 `活跃计划/项目总结.md`
- ❌ **计划正文** → 在各自的计划容器里

**为什么这一节重要**：入口文件一旦开始复述内容，它就会膨胀、然后和权威分叉，
最终没人读它 —— 而它的全部价值就是「告诉人从哪开始读」。

4. …
```

## 写法纪律

1. **不超过一屏半。** 它膨胀的那一刻就失去了作为「入口」的价值 ——
   人会直接跳过它去猜。
2. **阅读顺序必须写全「为什么读它」**。只列文件名，人不会知道第 5 站才是真正的起点。
3. **§四、§六 只放最常撞到的几条**，指向宪法段取全量。
   **把全部规矩抄一遍，等于把宪法复制成两份** —— 两份必然分叉。
4. **不要在这里写计数。** 计数指向 `计划队列/队列总表.md`。
