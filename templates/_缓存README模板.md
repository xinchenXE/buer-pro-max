# `缓存/` README 模板（可选容器） 【可选 · 触发：门禁/走查会产生日志】

> **它回答：生成物放哪。** 一句话版：**所有不是人写的东西，都放这里，都不放仓库根。**
>
> 没有这个容器时，门禁日志、一次性脚本、`.diff` 会散在仓库根 ——
> 然后某一天有人分不清哪个文件是源码、哪个是刚才跑门禁的产物。

---

## 模板

```markdown
# 缓存 · 生成物归置处

> **本目录的一切内容都是生成物，不是人写的。**
> 它应当被版本控制**忽略**（写进 `.gitignore`）。**不忽略它就是错的** ——
> 生成物进版本控制会让每次 diff 都被噪音淹没。

## 一、放什么

| 子目录 | 放什么 | 命名 |
|---|---|---|
| `门禁与走查日志/` | 每道门的输出、走查日志 | `<日期>-<轮次>-<门>-<slug>.log` |
| `一次性脚本/` | 用完即弃的临时脚本（探针、批量改写） | `<日期>-<slug>.{js,py,ps1}` |
| `diff/` | `.diff` / `.patch` / `.orig` / `.rej` / `.bak` | 原名 |

## 二、两条纪律

### 1. 一切生成物落这里，**不得写仓库根**

**为什么**：仓库根应当只有**代码与配置**。生成物一旦落到根目录，
它会被误当成源码、会被误提交、会在下次清理时被误删。

### 2. **原文件名一律不改**

日志与 diff 一旦写就，**文件名就不再改** —— 计划文档、轮次记录、
偏差记录会**按裸文件名**引用它们作为验证证据。改个名，引用就全断。

## 三、不在这里放什么

- ❌ **人写的东西**（文档、源码、配置）—— 那些进版本控制
- ❌ **需要长期保留的证据** → 那进 `<证据目录>/`（走查截图、审计输出）
- ❌ **不可恢复的回滚材料** → 那进 `<快照目录>/`（**只增不覆盖**）

> **判断口径**：**这份东西丢了会怎样？**
> 无所谓 → 缓存；**要作为证据被引用** → 证据目录；**是退路** → 快照目录。

## 四、清理

缓存可以清理，**但清理前先确认没有计划文档按裸文件名引用它**。
**清空缓存不该让任何一道门禁变红** —— 如果会，说明有东西放错了地方。
```

---

## 什么时候生成本容器

| 情况 | 建议 |
|---|---|
| 项目已有 `.gitignore` 的忽略目录约定 | **可以不生成** —— 沿用现有约定即可 |
| 门禁与走查会产生日志、且有"原文件名不改"的引用需求 | **生成** |
| 仓库根已经开始出现散落的生成物 | **生成**（并清理根目录） |

> **触发信号**：**第一次有人把生成物写在了仓库根。**
> 那一刻就是建这个容器的时机 —— 再晚，根目录就定型了。
