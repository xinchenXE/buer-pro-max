## 文件头（一次性写）

```markdown
# 项目总结

> **逐轮记录。每轮一章，只追加，不改写。**
> 章节号与轮次号一一对应（见 `../计划队列/队列总表.md` §一）。
> **§一–§<N> 已冻结为历史章节**，正文不改；更正走「注记」而不是改写。
>
> **与相邻文档的分工**：
> - 本文件 = **每一轮做了什么与为什么**（叙事）
> - `../代码修改记录/` = **哪个文件哪一行改成什么、用什么命令验的**（逐文件证据）
> - `README.md` §四 = **最近 3 轮摘要**（定长窗口，不累积）
```

## 轮次章节模板（每轮追加一节）

```markdown
## §<章节号> <轮次号> · <主题>（<起止日期>）

> 派发件：`../归档计划/<...>.md`（闭环后路径）｜问题源：`ISS-NNN`
> 可改档：<...>｜硬停：<本轮撞到的>

### 落地

<**做了什么**。按任务编号逐条对应计划，说清实际做法与计划是否一致。
不一致的**不在这里辩解** —— 记进 §偏差，这里只写事实。>

- <任务 1>：<实际做了什么>
- <任务 2>：<实际做了什么>

### 验证

| 门 | 结果 |
|---|---|
| | |

- **人工/视觉验证**：<N 景 M PASS / 无法验证的原因>
- **证据**：`../证据/<...>`｜快照 `snap-<日期>-<slug>`

### 偏差

<**编号列出**。每条一两句，权威原文在计划文档的「偏差记录」节。
跨轮的偏差登记为 `DEV-NNN` 并给路径。无偏差就写「无功能性偏差」。>

- <发生了什么> —— <怎么处置>

### 仍开放

<**这一轮做完之后，还剩下什么没做。** 这一节最容易被漏掉，
而它恰恰是下一个会话最需要的 —— 没有它，未完成的工作看起来像从未存在过。>

- <未完成项> → 去向：<新的活跃计划 / 队列项 NNN / 休眠>
- <已知缺口> → <触发条件>
```

---

## 四条写法纪律

1. **「仍开放」必填。** 哪怕写「无」。没有这一节，读者无法区分
   「这轮全做完了」与「这轮只做了一部分但没说」。
2. **「偏差」不在这里辩解。** 权威原文在计划文档；这里只给**条目 + 去向**。
   两边都写全文 = 双份记录 = 必然分叉。
3. **不改写历史章节。** 发现旧章节有错 → 在**原地加一条注记**写明更正，
   正文保留。**历史的价值恰恰在于它记录了当时的错误认知。**
4. **章节号即轮次号。** 不要另起一套编号 —— 它是 ID 序列的一部分，
   别处的引用都靠它定位。

## 与相邻文档的分工

| 文件 | 粒度 | 可改性 |
|---|---|---|
| 本文件 | 每轮一段叙事 | **只追加** |
| `../代码修改记录/` | 每个文件每处改动 | 追加式 |
| `README.md` §四 | 最近 3 轮，一句话 | 滚动覆盖（定长窗口） |
| 计划文档的「验证记录」节 | 本轮的逐门结果 | 闭环后随计划**冻结** |
| 计划文档的「偏差记录」节 | 本轮偏差的**权威原文** | 闭环后随计划**冻结** |
